## 3. 줄 무늬 명세의 형식

```
줄명세/
  책.json        형식("줄무늬 1") · 시트 순서 · 통합문서의 정의된 이름
  S05.jsonl      첫 줄 = 시트 머리, 둘째 줄부터 행 하나씩 (JSON Lines)
  옛서식/        옛 서식을 그대로 옮기는 길의 재료(서식 표 · 칸별 서식 번호 · 행 높이). 지워도 명세는 읽힌다
  테마.xml
```

**시트 머리(첫 줄)** — `시트`(ID) · `이름`(탭 이름) · `열`(열 등록부: `id` · `옛` 열 글자 · `종류` · `폭`) · `축`(시간축을 이루는 열 종류) · `묶음`(묶음 이름 → 열 종류들) · `쓰임`(쓰임 이름 → {별칭: 열 ID}) · `속성`(탭 색 · 틀 고정 · 인쇄 …) · 여러 줄 병합 · `유효성` · `조건부서식` · `정의된이름`.

**행 한 줄**

```json
{"id":"S05R017","이름":"매출원가 합계","단위":"=[$S12R006 금액 단위 라벨]@$값2","종류":"합계","서식":"금액",
 "무늬":{"실적":"=[S13R063 매출원가]@.","예측영구":"=SUM([S05R010 원가 항목 1]@.:[S05R016 신제품·증설 원가]@.)"}}
{"id":"S02R068","이름":"주당가치","단위":"=[$S12R007 주당 단위 라벨]@$값2","종류":"합계","서식":"금액","쓰임":"단일",
 "무늬":{"값":"=IFERROR([$S02R066 주주가치]@$값*[$S12R008 주당가치 환산 배율]@$값2/[$S02R067 발행주식수]@$값,0)"}}
```

| 항목 | 뜻 |
|---|---|
| `id` | 행 ID. `S05R017` = 5번 시트의 17번(가정 번호). 배치를 바꿔도 안 바뀐다 |
| `이름` · `단위` | 이름 열 · 단위 열의 글. 「=」로 시작하면 손 수식 |
| `종류` | 제목 / 구획머리 / 머리 / 입력 / 계산 / 소계 / 합계 / 비율 / 점검 / 글 / 빈줄 |
| `서식` | 숫자 서식 이름 — `서식표준.서식표` 의 키(금액 · 비율 · 비율2 · 연수 · 날짜 …) |
| `무늬` | 열 구간 → 손 수식. 구간 안의 칸마다 같은 글을 그 칸의 열에서 읽는다 |
| `글` · `값` | 열 구간 → 글 / 숫자·날짜·참거짓 |
| `입력` | 입력 칸인 열 구간(빈 칸이어도 입력 서식을 입는다) |
| `병합` | 이 줄 안의 병합(열 구간) |
| `쓰임` | 이 줄의 열 별칭 묶음(점검 · 설정 · 시점 · 단일 · 시나리오) |
| `선` · `들여` · `굵게` | (있을 때만) 소계/합계 줄선 · 이름 칸 들여쓰기 · 굵은 글씨 — 표준 서식 길에서 쓴다(`2_배치_서식.md` 7-1) |

**열 구간** — `E1`(열 하나) · `E2~E7`(열 ID 구간) · `예측`(묶음 전부 — 그 종류의 열이 늘면 따라 는다) · `E2~예측`(E2 부터 예측 묶음의 끝까지) · `실적~E3` · `판정`(그 줄 쓰임의 별칭).

스캐폴드의 수: 행 1,211 · 수식 칸 4,800 → 무늬 1,187구간(둘 이상 묶인 것 354) · 글 칸 2,627 → 2,240구간. 줄 종류: 입력 349 · 계산 247 · 비율 134 · 점검 127 · 구획머리 91 · 글 75 · 합계 74 · 빈줄 68 · 머리 33 · 제목 13. 쓰임: 점검 140 · 단일 56 · 시나리오 21 · 설정 15 · 시점 14줄.

줄 종류 · 서식 이름 · 입력 칸은 옛 서식(바탕색·글자 크기·숫자 서식)과 수식 구조에서 **가늠한 것**이다. 이름표·배치 설계가 명세에서 고쳐 쓴다. 한 가지는 구조로 정했다: 머리 줄의 수식이 바로 아래 세 줄을 `INDEX` 로 읽으면 그 세 줄은 「입력」이다(옛 서식에 입력 바탕이 없던 뒤쪽 구획 108줄이 「글」에서 「입력」으로 바로잡혔다).

### 기간 열을 가정 파일이 정하게 될 때(`5_기간열_결함.md` 2장) — 어떻게 받치는가

이번에 구현하지는 않았다. 형식이 받치는 것:

1. **무늬와 범위는 열 글자가 아니라 열 종류로 적혀 있다.** 열 구간 열쇠 1,339개 가운데 묶음 이름 497 · 묶음 끝에 닿는 구간 20 · 쓰임의 별칭 228 · 시간축 아닌 열 470 이고, 시간축 열 ID 를 못 박은 것은 124개다. 무늬의 수식 글에 적힌 열 표기 7,126개 가운데 같은 열 1,332 · 이웃 열 89 · 묶음 1,738 · 별칭 1,392 · 시간축 아닌 열 1,688 이고, **시간축 열 ID 를 못 박은 것은 887개**다(`python 분석_열쓰임.py`).
2. **열을 더하는 방법이 있다.** 배치의 열 목록에 `{"새열": "E12", "종류": "예측"}` 을 넣으면 그 종류의 묶음이 는다 — `@예측` 범위, `예측` · `E2~예측` 무늬, `@-1`(시간축 열끼리 센다), `@예측.끝` 이 따라간다. 서로 짝인 범위(다른 시트의 `MATCH` ↔ `INDEX`)는 크기가 같은지 본다 — 한 시트에만 더하면 오류다. 시험 7: 예측 열 하나를 9장에 더해 새 열에 수식 296칸이 들어가고 옛 칸 7,360칸의 값이 그대로다.
3. **열을 줄일 때 막히는 곳이 곧 고칠 목록이다.** 마지막 예측 열(E11)을 빼면 오류 8건 — `E11` 을 열 ID 로 못 박아 읽는 7칸(1번 32·33·34·39행, 2번 53행, 7번 32행, 8번 56행)이다. `@$예측.끝` 으로 고쳐 쓰면 풀린다.
4. **남은 일(3단계)** — 못 박은 887개의 뜻을 가려 자리 이름으로 고친다. 갈래: `@H3` 552(13번 371 · 11번 → 13번 149 — 「기준일 열」= `실적.끝`) · `@E1` 181(첫 예측 열 = `예측.첫`) · `@TV` 109(영구 열은 하나라 그대로 둬도 된다) · `@H2` 14 · `@H1` 12 · `@E2` 9 · `@E11` 7 · `@E3` 3. 명세가 글이므로 `@$H3` → `@$실적.끝` 같은 치환으로 고치고, 시험 1(칸 단위 일치)로 값이 안 바뀐 것을 확인하면 된다. 무늬 열쇠의 `E1` · `H1~E1` · `E1~E6` 따위(124개)도 같다.
5. 열 등록부(시트 머리의 `열`)를 가정 파일의 `기간`에서 짓는 단계가 하나 필요하다 — 실적 n열 · 누계 0/1열 · 잔여 0/1열 · 연간 m열 · 영구 1열. 지금 구조에서는 배치의 `열` 목록을 그렇게 만들어 주면 된다(열 ID 는 `H1`… 대신 기간 ID `FY2025A` 를 써도 된다 — 열 ID 는 이름일 뿐이다). 좌표 지도의 `기간열` · `열ID` · `묶음` 이 그 결과를 싣는다.
6. 숫자로 적힌 자리(12번 247행 「둔화층 시작 열 위치」= 7, 28행의 `MATCH` 결과)는 예측 묶음 안의 순번이다. 묶음이 통째로 움직이면 맞지만 열 수가 바뀌면 틀린다 — 틀이 볼 수 없는 것이다(원형 검증 4절). 산식에서 없앨 대상이다.

## 5. 손 수식 문법 (요약 — 전문은 `수식문법.md`)

```
=[S04R054 매출액 합계]@. - [S05R017 매출원가 합계]@.     같은 열(@.)
=[S04R054]@. / [S04R054]@-1 - 1                          직전 열(@-1) · 다음 열(@+1). 시간축 열끼리 센다
=[S12R024 기간 길이]@$E1                                 고정 열(열 ID). $ 는 절대 표시(값에는 영향 없다)
=[$S12R013 시나리오 번호]@$값                            그 줄 쓰임의 별칭
=SUM([S05R010]@.:[S05R016]@.)                            범위
=INDEX([$S04R054]@$예측,[$S12R028]@$값)                  열 묶음(같은 줄의 「예측」 열 전부)
=COUNT([S12R031]@예측영구:[S12R033]@예측영구)            여러 줄 × 열 묶음
=[$S02R034]@$예측.끝                                     묶음의 끝 열(첫 열은 .첫)
```

- 행은 **ID 로** 부르고 이름은 덧붙이는 주석이다(`[S04R054 매출액 합계]`). 다른 시트는 적지 않는다 — 행 ID 가 시트를 안다.
- 덧붙인 이름이 지금 줄 이름(전체 또는 짧은 이름)과 다르면 **경고**한다(오류 아님). 줄 이름을 한꺼번에 고친 뒤에는 `python 줄무늬.py --다시쓰기 줄명세` 로 덧붙인 이름을 맞춘다(시험 4 마: 한 줄 이름을 고치니 경고 162곳 → 다시쓰기 뒤 0).
- 원형의 `@c` · `@c-1` 을 `@.` · `@-1` 로 바꿨다. `[행]@.-1` 은 「같은 열에서 1을 뺀다」, `[행]@-1` 은 「직전 열」이다(원형 검증 결함 6-① 을 닫았다).
- **좌표를 그대로 쓰면 오류다**(`=G54*2`). 모르는 행 ID · 모르는 열 · 없는 이웃 열도 오류다.
- 문자열 상수 안은 건드리지 않는다. 열 전체(`[S12*]@$여백:[S12*]@$단위`) · 행 전체(`[$S12R003]@*:[$S12R007]@*`) · 정의된 이름 · 못 바꾸는 참조(`⟦원문⟧`)도 적을 수 있다.
- 손 수식도 명세의 수식과 **같은 길**(`_틀짜기`)로 틀이 된다. 감싼 함수(`INDEX` 따위)가 같이 붙으므로 범위 점검이 똑같이 걸린다.

## 6. 짓기 본체

`짓기(명세, 배치, 낼 xlsx, 좌표지도 json, 서식길="옛"|"표준"|"없음")`. 명세는 줄 무늬 명세 폴더(또는 칸 단위 명세 폴더), 배치는 dict/JSON 이다. 배치의 모양은 `짓기.py` 머리의 설명에 있다 — 시트마다 `이름` · `행`(행 ID 의 새 순서, `{"새줄": …}`, `{"빈줄": n}`) · `열`(열 ID 의 새 순서, `{"새열": …, "종류": …}`) · `뺄줄` · `뺄열` · `숨길줄` · `숨길열` · `묶음`(줄 묶음 접기) · `열묶음` · `새이름` · `덧칸` · `줄서식` · `틀고정` · `인쇄` · `조건부서식` · `유효성`, 그리고 맨 위에 `별칭` · `뺄시트`.

### 점검 — 오류가 하나라도 있으면 파일을 내지 않는다

원형의 것(유지): 줄·열을 배치에서 빠뜨림 · 범위 안에 낯선 줄·열 · 범위 양 끝 뒤집힘 · 범위 안 순서 바뀜 · 범위에 있던 줄이 밖으로 · 뺀 줄·열을 가리킴 · 위치로 읽는 범위의 가운데 줄 빼기(오류) / 합계 범위의 가운데 줄 빼기(경고) · 수식 8,192자 넘김.

이번에 더한 것:

| 점검 | 답 |
|---|---|
| **서로 짝인 범위** — 한 함수가 자리끼리 짝지어 읽는 범위들(`SUMPRODUCT` · `COUNTIFS` …), `INDEX` 의 범위 ↔ 그 위치를 낸 `MATCH` 의 범위(위치 인자가 다른 칸이면 그 칸의 수식을 따라간다 — 다른 시트여도) | 새 배치에서 크기나 열 차례가 달라지면 오류. 스캐폴드에서 한 함수 안의 짝 302 · `INDEX`↔`MATCH` 짝 82쌍을 본다 |
| **범위에 줄을 더하는 규칙** — `범위허용`(범위 안에 낀 줄) · `범위에넣기`(범위 끝에 바로 붙인 줄) | 합계 따위면 범위가 넓어진다. **위치로 읽는 범위(`INDEX` · `MATCH` · 짝 범위)면 오류**. 표시를 단 줄이 어느 범위에도 안 들면 경고 |
| **범위 안의 빈 줄**(`빈줄` · 행 번호 못 박기) | 위치로 읽는 범위와 빈 칸에 값이 달라지는 함수(`COUNTBLANK` 따위)가 읽는 범위면 오류, `SUM` · `MAX` · `MIN` · `COUNT` · `AVERAGE` 면 경고 |
| **묶음** — 묶음의 열 사이에 다른 열 · 시간축 열의 차례 바뀜 | 오류 |
| **시트** — 명세에 없는 시트에 줄을 실음 · 같은 시트를 두 번 적음 · 다른 시트의 줄을 실음 · 시트를 빠뜨림 | 오류(전에는 줄이 말없이 버려지거나 `KeyError` 로 멈췄다) |
| **배치의 오타** — 모르는 열쇠 · 놓이지 않은 행·열 ID 를 적은 `새이름` · `줄서식` · `숨길줄` · `덧칸` · `뺄줄` · `뺄열` · 이름 칸이 빈 줄의 `새이름` | 오류 |
| 배치가 준 `묶음` · `인쇄` · `조건부서식` · `유효성` 의 모르는 ID | 오류 |
| 수식에 덧붙인 이름이 지금 이름과 다름 | 경고(줄·이름 짝마다 한 번) |
| 자리가 바뀐 배치의 **글 속 좌표**(「E28」「12번 30행」) | 경고 한 건 — 스캐폴드 232칸. 옮기지는 않는다 |

### 새 시트 · 인쇄 · 줄 묶음 · 조건부 서식

- **새 시트**는 줄 무늬 명세 파일 하나로 준다 — `명세읽기(폴더, 덧파일=[S14.jsonl, S15.jsonl])`. 열 등록부를 그 파일의 머리에 적고, 수식은 같은 문법으로 다른 시트의 줄을 부른다(`=[S02R079 시트 상태]@판정`). 옛 서식이 없으므로 명명 스타일을 입는다. 새 시트가 가리키는 줄을 빼면 오류로 잡힌다.
- **인쇄**: 방향 · 용지 · 폭/높이 맞춤 · 제목 행(행 ID 두 끝) · 제목 열 · 영역 · 바닥글 · 여백 · 쪽 나눔. **줄 묶음 · 열 묶음**: 두 끝 ID · 수준 · 숨김(요약 줄에 `collapsed`). **조건부 서식**: 값 비교 또는 손 수식. **목록 유효성**. 엑셀로 열어 다시 저장한 뒤에도 남는 것을 시험 2가 본다.
- 지은 워크북에 **배치의 지문**을 사용자 지정 속성(`DCF_좌표지도_지문`)으로 남긴다. 키트의 `좌표.확인` 이 다른 배치의 지도와 짝지은 것을 가려낸다.

### 서식 — 두 길

- **`옛`**: 옛 서식을 있는 그대로 옮긴다(`옛서식/` 의 칸별 서식 번호). 스캐폴드와 서식 9,485칸 · 병합 148 · 유효성 82칸 · 틀 고정 13 · 열 폭 202 · 행 높이 243 이 같다. 옛 서식이 없는 시트(새 시트)는 이 길에서도 명명 스타일을 입는다.
- **`표준`**: 칸 종류 → 명명 스타일(`서식훅.py`). 칸 종류는 줄의 종류 · 열의 종류 · 칸의 내용(입력 칸인가 · 수식인가 · 다른 시트를 그대로 읽는가 · 글인가)에서 정한다.

  | 칸 종류 | 명명 스타일 | | 칸 종류 | 명명 스타일 |
  |---|---|---|---|---|
  | 제목 | `글_제목` | | 입력 | `값_입력` |
  | 구획머리 | `글_구획` | | 입력글 | `값_입력글` |
  | 머리 | `머리_띠` | | 계산 | `값_계산` |
  | 행이름 · 주석 | `글_행이름` · `글_주석` | | 연결 | `값_연결` |
  | 단위 · 번호 · 근거 | `글_단위` · `글_번호` · `글_출처` | | 글값 · 판정 | `값_글` · `점검_표시` |

  숫자 서식은 줄의 `서식`(서식표의 키)으로, 소계·합계 줄선은 `서식표준.줄선` 으로, 줄의 `들여` · `굵게` 는 덧씌워 입힌다. `설계/서식표준.py` 의 `기본글꼴` · `스타일등록` · `서식표` · `줄선` 만 쓴다(파일이 없으면 칸 종류만 가리고 서식은 안 입힌다).
- 표준 길은 **훅만** 만든 것이다. 열 폭 · 행 높이 · 머리 띠 · 틀 고정 · 접기의 표준(`시간축시트틀` · `머리3행` 따위)은 입히지 않았다 — 다음 단계의 일이다. 값에는 영향이 없다(시험 2: 표준 길로 하이닉스를 옮겨 지어 재계산한 7,283칸 다름 0 · 명명 스타일 14가지 11,405칸).

## 10. 남은 한계

1. **줄은 배치로 시트를 옮길 수 없다.** 행 ID 가 시트를 정한다. 검증 블록을 `15. 검증` 으로 모으는 일(결정 6)은 배치가 아니라 **명세를 고쳐서** 한다 — 15번의 줄로 수식을 다시 적고(수식 글은 행 ID 로 적혀 있어 어느 시트에 놓아도 뜻이 같다. `@.` · `@판정` 같은 열만 그 시트 것으로 바꾼다) 옛 줄을 빼고, 옛 줄을 가리키던 수식(시트 상태의 `COUNTIF` 범위 따위)을 고친다. 뺀 줄을 가리키는 참조가 남으면 짓기가 오류로 알린다.
2. **범위 안의 줄 순서는 배치로 못 바꾼다**(합계 범위여도 오류). 계정 순서를 바꾸려면 줄 무늬 명세에서 줄을 옮긴다. 그때 범위의 뜻은 「명세 순서에서 두 끝 사이」가 되므로, 옮긴 줄이 범위에서 빠지지 않았는지는 값 대조로 본다(명세 자체를 고친 것은 짓기가 점검하지 않는다).
3. **글 속 좌표는 안 옮긴다**(232칸 — 글 칸 184 · 수식 속 문자열 48). 경고만 한다. 글에서 좌표를 빼고 번호 + 이름으로 부르는 것이 근본이다(결정 2·4).
4. **줄 종류 · 서식 이름 · 입력 칸은 가늠이다.** 옛 서식에서 읽었다. 예: 12번 126행 「기말 인원수」의 서식이 「금액」으로 잡혀 있다. 표준 서식 길로 납품본을 지으려면 이름표·배치 설계가 명세의 `종류` · `서식` · `선` · `들여` 를 손봐야 한다.
5. **표준 서식 길은 칸 스타일만 입힌다.** 열 폭 · 머리 3행 · 시점 머리 · 안 쓰는 열 접기 · 점검 조건부 서식의 표준은 `서식표준.py` 의 시트 함수(`시간축시트틀` 따위)가 하는 일인데 아직 잇지 않았다. 배치의 `인쇄` · `묶음` · `조건부서식` · `틀고정` 으로 줄 수는 있다.
6. **값 대조는 스위치 한 값(파일에 든 시나리오)에서만 한다.** `INDEX` 가 고르지 않은 두 시나리오 줄은 값에 닿지 않는다. 그 빈틈은 구조 대조가 메운다(참조가 같은 줄·열을 가리키는지는 값과 무관하게 전수로 본다). 다만 구조 대조는 **옛 파일에 있던 수식만** 본다 — 새 줄·새 시트의 손 수식은 값으로만 확인한다(시험 2의 29칸 · 20건).
7. 구조 대조는 범위가 일부러 넓어진 배치(범위허용 · 범위에넣기 · 묶음에 열을 더함)에는 못 쓴다 — 넓어진 범위가 「다름」으로 나온다.
8. **조건부 서식의 상대 수식**은 범위 첫 칸 기준으로만 옮긴다. `좌표지도.수식옮기기` 는 범위 점검을 안 한다(양 끝만 옮긴다). 원형과 같다.
9. 안 옮기는 것: 시트 보호, 차트·그림·표, 글 안의 부분 서식, 링크의 대상 주소, 옛 파일의 인쇄 제목 행·영역(좌표 글 — 배치의 `인쇄` 로 준다). 스캐폴드에는 이런 것이 없다.
10. 지은 파일에는 값 캐시가 없다(엑셀로 재계산해 저장해야 한다 — 워크북 마감의 일). `formulas` 라이브러리로는 재계산해 보지 않았다.
11. `범위에넣기` 는 그 줄이 끝인 **모든**(위치로 읽지 않는) 범위를 넓힌다. 「이 범위에만 넣는다」고 가려 적는 수단은 없다.
12. 덧붙인 이름은 줄 이름에서 기계적으로 줄인 것이다(줄표·괄호·쌍점 앞까지 24자). 이름이 긴 안내 글인 줄(12번 28행)은 덧붙인 이름도 길다. 이름표가 줄 이름을 고치고 `다시쓰기` 를 돌리면 정리된다.
13. `새시트/S14.jsonl` · `S15.jsonl` 과 `배치_옮김.py` 는 시험용이다. 번호 열의 번호는 이름 있는 줄 전부에 기계적으로 붙였다.

## 11. 다음 단계가 알아야 할 것

1. **정본 후보는 `줄명세/` 다.** 산식·이름·종류를 고칠 때는 이 폴더의 JSONL 을 고친다. 고친 뒤 `python 줄무늬.py --다시쓰기 줄명세` 를 돌리면 표준 꼴(덧붙인 이름 · 별칭 · 묶음)로 다시 쓰인다. `시험_1` 은 `줄명세/` 를 스캐폴드에서 **새로 뽑아 덮어쓴다.** 명세를 손으로 고치기 시작하면 먼저 `줄명세/손으로_고침.txt` 를 만들어 둔다 — 이 파일이 있으면 시험이 `줄명세/` 를 건드리지 않고 `산출/줄명세_스캐폴드` 에 뽑는다(확인했다). 그 뒤로 시험 3·5 는 고친 명세를 읽으므로 기대값(시험 속에 적힌 수식 글)을 함께 고쳐야 하고, 고친 명세는 「옛 워크북과 값이 같다 + 일부러 바꾼 칸 목록」으로 닫는다(`대조도구.값대조` 의 `제외`).
2. **명세를 고쳐 값이 바뀌지 않았는지 보는 순서**: 짓기(같은 배치) → `구조대조.py`(참조가 같은 줄·열을 가리키는가) → 엑셀 재계산 → `값대조`. 열 ID 를 자리 이름으로 고치는 일(`@$H3` → `@$실적.끝`)은 지은 수식 글이 글자 그대로 같아야 하므로 `글대조` 로 닫힌다.
3. **새 탭 이름**은 배치의 `이름` 으로 준다(`8. CAPEX_working` · `9. NWC_working` · `14. 민감도` · `15. 검증`). 명세의 시트 머리 `이름` 을 고쳐도 된다. 수식 속 시트 이름은 따라 바뀌지만 **글 속의 탭 이름**(「8. CapEx_working에서 연동됩니다」)은 안 바뀐다.
4. **새 가정 줄의 번호는 숫자**로(`S12R501`). 숫자가 아닌 행 ID 는 좌표 지도의 번호 조회·가정묶음·단위에 안 실린다.
5. **키트 결합**: 생성기가 낸 좌표 지도를 스캐폴드 곁에 `DCF_워크북_좌표지도.json` 으로 두면 키트 사본의 붓기·대조가 그대로 읽는다(`좌표지도보강.py` 는 안 돌려도 된다). 지도의 `명세` · `원본` 에는 절대 경로가 들어 있다 — 키트에 넣을 때 파일 이름만 남긴다. `기간열` 은 12번 시트의 시간축 열을 옛 열 글자로 싣는다(새 열은 열 ID). 열 수를 바꾸면 엔진 배열(15칸)과 붓기의 「앞 3칸은 실적」 판단을 함께 고쳐야 한다.
6. **`서식표준.py` 와 맞춘 곳**: 스타일 이름 14개(6절 표), `서식표` 의 키(줄의 `서식`), `줄선(ws, 행, 열1, 열2, 종류)`, `기본글꼴(wb)` · `스타일등록(wb)`. 스타일 이름이나 함수 서명을 바꾸면 `서식훅.py` 의 `훅표` 를 함께 고친다. 날짜 값은 어느 칸에서든 `서식표["날짜"]` 를 입힌다(글 서식 `@` 칸에 날짜 상수가 들어가면 일련번호로 보인다 — 12번 평가기준일 칸에서 확인하고 고쳤다).
7. **결정에 대한 보완 요청**(바꿔야 할 근거는 못 찾았다):
   - 결정 5절 「안 쓰는 예측 열은 접어 숨긴다」와 기간 설계 2.1 「안 쓰는 예측 열이 없다」가 다르다(원형 검증 7-3). 뒤쪽이면 `INDEX(…,$값)` 로 마지막 예측 열을 고르는 수식과 길이 0 처리 수식이 사라지므로 3단계의 산식 범위가 달라진다. 생성기는 두 쪽 다 지을 수 있다.
   - 결정 1절 2단계의 합격 기준에 「구조 대조 0」을 넣기를 권한다. 값 대조만으로는 값이 0 인 칸(숫자 수식의 60%)의 틀린 참조를 못 잡는다.
8. 엑셀은 `엑셀재계산.재계산` 만 쓴다(`DispatchEx` 로 따로 띄우고, 자기가 연 통합문서만 닫고, 자기가 띄운 엑셀만 `Quit`). 읽을 파일은 읽기 전용으로 열고 다른 이름으로 저장한다.

## 12. 실행 방법

```
cd C:/Users/Public/키트개편/구현/생성기

python 모두돌리기.py                  # 시험 일곱 가지 전부 (엑셀을 따로 띄운다. 2분 반 ~ 5분)
python 모두돌리기.py --자세히          # 시험마다 출력 전부
python 모두돌리기.py --엑셀생략        # 이미 재계산한 파일을 다시 써서 대조만

python 명세추출.py <읽을 xlsx> <칸 단위 명세 폴더>
python 줄무늬.py <칸 단위 명세 폴더> <줄 무늬 명세 폴더>          # 열표를 입혀 줄 무늬로 묶는다
python 줄무늬.py --다시쓰기 <줄 무늬 명세 폴더>                   # 읽어서 표준 꼴로 다시 쓴다(덧붙인 이름 맞춤)
python 짓기.py <명세 폴더> 같은배치 <낼 xlsx> [<낼 좌표지도 json>]
python 짓기.py <명세 폴더> <배치 json> <낼 xlsx> [<좌표지도 json>] [--서식 옛|표준|없음] [--덧명세 새시트/S14.jsonl 새시트/S15.jsonl]
python 배치_옮김.py <줄 무늬 명세 폴더> <낼 배치 json>            # 시험용 옮긴 배치
python 구조대조.py <옛 xlsx> <새 xlsx> <좌표지도 json>            # 값과 무관한 구조 대조
python 엑셀재계산.py <읽을 xlsx> <낼 xlsx>
python 분석_열쓰임.py [<줄 무늬 명세 폴더>]                       # 시간축 열을 어떻게 부르는지 센다

python 시험_1_줄무늬일치.py [--전부]     python 시험_2_옮겨짓기.py [--엑셀생략]     python 시험_3_깨지는배치.py
python 시험_4_문법왕복.py               python 시험_5_붓기흉내.py [--엑셀생략]     python 시험_6_합성.py [--엑셀생략]
python 시험_7_열늘리기.py [--엑셀생략]
```

- 시험 1 이 `줄명세/` 를, 시험 2 가 하이닉스의 줄 무늬 명세와 옛 재계산본을 만든다. 3·5·7 은 그것을 쓴다(따로 돌릴 때는 1 → 2 를 먼저).
- 파이썬 3.11 · openpyxl 3.1.5 · pywin32. 콘솔 출력은 UTF-8 로 맞춘다(`sys.stdout.reconfigure`).
