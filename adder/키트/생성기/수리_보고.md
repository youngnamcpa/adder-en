## 3. 남은 한계 — 못 고친 것은 없으나 알아야 할 것

1. **13번의 검증 구획은 지금 수식으로는 15번으로 못 옮긴다.** 13번 111·113번 줄의 판정 수식은 13번 칸을 수백 번 읽는다. 15번으로 가면 참조마다 `'13. 원천_재무제표'!` 가 붙어 9,798자가 된다(엑셀의 한 칸 수식 한도 8,192자). 짓기가 「수식 길이」 오류로 막는다(시험 9 「깨지는 경우」). 수식을 보조 칸으로 나눈 뒤(3단계의 일)에 옮길 수 있다. 시험의 배치는 13번을 빼고 12개 시트를 모은다.
2. **옮긴 줄은 놓인 시트에 더한 묶음 열로 늘지 않는다.** 묶음으로 적은 무늬가 새 열까지 느는 것은 본 시트에 놓인 줄뿐이다. 열을 더하는 일 자체가 지금은 막혀 있어(ⓓ) 걸리는 곳이 없다.
3. **열 구간 열쇠에 못 박은 열 ID**(무늬의 `E1` · `H1~E1` 따위 124개)는 「못 박은 열」 오류가 세지 않는다. 수식 속 참조만 센다. 열 구간에는 「묶음의 첫 열」만 가리키는 표기가 없어, 3단계에서 기간 열을 풀 때 표기부터 정해야 한다.
4. **범위 지문은 여러 줄 범위만 적는다.** 한 줄짜리 범위(같은 줄의 열 범위)의 열 구성은 묶음·짝 범위 점검이 본다.
5. **글 속 좌표는 여전히 안 옮긴다**(경고 한 건). 줄을 15번으로 모으면 「사유는 E28」 같은 글이 더 많이 낡는다. 글에서 좌표를 빼는 것은 이름표의 일이다.
6. 구조 대조는 범위가 일부러 넓어진 배치(범위허용 · 범위에넣기 · 틈허용 · 묶음에 열을 더함)에서는 그 범위를 「다름」으로 낸다(전과 같다).
7. 판별력은 값 대조만으로 100%가 아니다. 참조 하나를 어긋나게 고친 400칸 가운데 고친 칸의 값이 달라진 것은 하이닉스 자료 262칸(66%), 지문 자료 358칸(90%)이다. 나머지는 구조 대조가 잡는다(400칸 가운데 400칸).

## 5. 다음 단계가 알아야 할 것

### 5-1. 배치로 줄의 시트 이동을 적는 법

행 ID 의 `S04` 는 「명세의 4번 시트 파일에 적힌 줄」이라는 이름일 뿐이다. 놓이는 시트는 배치가 정한다.

```json
{"시트": [
  {"id": "S04", "행": ["S04R001", "…", "S04R057"]},
  {"id": "S15", "이름": "15. 검증",
   "열": ["번호", "이름", "단위", "판정글", "미결", "표시",
          {"새열": "판정", "폭": 44, "종류": "점검칸"}, {"새열": "사유", "폭": 44, "종류": "점검칸"},
          {"새열": "덧1", "종류": "점검칸"}, {"새열": "덧2", "종류": "점검칸"}],
   "행": ["S15R001", "…", {"빈줄": 1}, "S04R058", "S04R059", "…", "S04R065"],
   "열맞춤": {"S04": {"H1": "판정", "H2": "사유", "보조글": "덧1", "보조값": "덧2"}}}]}
```

- 옮길 줄을 놓을 시트의 `행` 에 적고 본 시트의 `행` 에서는 뺀다. `뺄줄` 에는 적지 않는다.
- `열맞춤` 은 「본 시트의 열 ID → 놓인 시트의 열 ID」다. 안 적은 열은 같은 ID 의 열에 놓인다(시간축 시트끼리는 적을 것이 없다). 값이 있는 칸의 열이 놓인 시트에 없으면 오류다.
- **수식은 안 고친다.** 짓기가 시트 머리만 다시 쓴다 — 옮긴 줄을 읽던 수식은 놓인 시트로, 옮긴 줄이 같은 시트의 다른 줄을 읽던 수식은 다른 시트 참조로, 같은 시트에 모인 줄끼리는 시트 머리 없이.
- 옮긴 줄의 수식과 그 줄을 가리키는 참조의 열 표기(`@판정` · `@H1`)는 본 시트의 것 그대로 둔다.
- 범위는 양 끝이 같은 시트에 놓였을 때만 선다. 범위의 줄은 통째로 옮긴다(일부만 옮기면 오류).
- 그 줄에 걸려 있던 목록 유효성은 줄을 따라간다(시험 9 — 12번의 유효성 걸린 줄을 15번으로). 조건부 서식도 같은 길로 따라가게 했으나 스캐폴드에 조건부 서식이 없어 줄을 옮긴 경우로는 시험하지 못했다. 줄 안의 병합은 병합에 든 열들이 놓인 시트에서도 붙어 있을 때만 남는다(검증 구획 머리의 「이름~영구」 병합은 15번에서 풀린다).
- 본 시트 배치의 `덧칸` · `새이름` · `줄서식` 은 따라가지 않는다(놓인 시트의 배치에 적는다).
- 시트를 통째로 빼면서(`뺄시트`) 그 시트의 줄 일부를 다른 시트에 실을 수도 있다(시험 6).
- 보기: `배치_옮김.검증모은배치(명세)` — 검증 구획을 15번으로 모으고 9번의 한 구획을 10번으로 옮긴다. `python 배치_옮김.py 줄명세 <낼 배치.json> --검증모음`.
- 좌표 지도: 옮긴 줄은 `행시트`(행 ID → 놓인 시트 ID)에, 열은 `열맞춤` 에 실린다. `지.새주소(옛 시트, 옛 칸)` · `지.주소(본 시트 ID, 번호, 열 ID)` · `지.가정행` 은 **놓인 시트의 이름**을 돌려준다. `지.놓인시트(행 ID)` 가 새로 생겼다. 줄을 옮긴 배치의 지문에는 `행시트` 가 들어간다(안 옮긴 배치의 지문은 전과 같다).

### 5-2. 범위 지문 승인 절차

명세에서 범위에 든 줄을 끼우거나 빼거나 옮기면, 또는 범위를 읽는 수식을 새로 적으면 짓기가 「범위 지문」 오류로 멈춘다.

```
python 범위지문.py 보기 줄명세 --덧명세 새시트/S14.jsonl 새시트/S15.jsonl     # 지문과 다른 곳(갈래별로)
python 범위지문.py 승인 줄명세 --덧명세 …                                     # 합계 범위만 바뀌었을 때 지문을 고쳐 적는다
python 범위지문.py 승인 줄명세 --덧명세 … --위치범위                           # 위치로 읽는 범위 · 가정묶음 · 짝 수까지 승인
```

1. `보기` 로 바뀐 목록을 읽는다. 뜻한 바와 같은지 본다(든 줄 · 빠진 줄 · 순서).
2. 구조 오류(뒤집힘 · 순환 · 가정 머리 줄 · 짝 크기)가 있으면 승인으로 못 푼다. 명세를 고친다.
3. 합계 범위만 바뀌었으면 `승인`. 위치로 읽는 범위(`INDEX` · `MATCH` · 짝 범위 · `COUNTBLANK` · `COUNTIF` …)가 바뀌었으면 `--위치범위` 를 붙여야 적힌다.
4. 급하게 한 번 지어 볼 때만 `python 짓기.py … --합계범위승인`(합계 범위의 바뀜을 경고로 낮춘다. 위치 범위는 안 풀린다).
5. `범위지문.json` 의 diff 가 승인의 기록이다. 명세와 함께 커밋한다. 손으로 고치지 않는다. 「다시쓰기」는 건드리지 않는다.

새 시트(`새시트/*.jsonl`)의 지문은 그 폴더의 `범위지문.json` 에 적힌다.

### 5-3. 명세를 고치는 순서

1. `줄명세/S*.jsonl` 을 고친다. 왜 고쳤는지는 그 줄의 `"메모"` 에 적는다. 코드로 고칠 때는 `줄무늬.시트읽기(경로)` → 고침 → `줄무늬.시트쓰기(경로, 머리, 줄들)`.
2. 줄 이름을 고쳤으면 `python 줄무늬.py --다시쓰기 줄명세`(덧붙인 이름을 맞추고 표준 꼴로 다시 쓴다. 안 맞추면 짓기가 멈춘다).
3. `python 범위지문.py 보기 줄명세 --덧명세 …` → 바뀐 범위를 확인하고 승인.
4. `python 짓기.py 줄명세 <배치> <낼 xlsx> <지도> --덧명세 …` — 종료 코드 0 이어야 한다(2 면 위험한 경고를 읽는다).
5. 구조 대조(`구조대조.명세대조(명세, 새 xlsx, 지도)`) → 엑셀 재계산 → 값 대조(스위치 세 값 · 일부러 바꾼 칸은 `제외` 로).
6. 커밋.

정본을 고치기 시작하면 시험 1 ⑧의 「스캐폴드에서 뽑은 것과 같다」가 「다르다」로 바뀐다 — 실패가 아니다. 시험 3·4·5·7·8 은 `산출/줄명세_스캐폴드`(시험 1 이 스캐폴드에서 뽑는 것)를 쓰므로 정본을 고쳐도 기대값이 흔들리지 않는다.

### 5-4. 그 밖에

- **명세의 형식이 바뀌었다(「줄무늬 2」).** 행 하나가 여러 줄에 걸칠 수 있다(400자 넘는 행 192개). 한 줄씩 `json.loads` 하면 안 읽힌다 — `줄무늬.시트읽기` 를 쓴다.
- 수리 전에 뽑아 둔 옛 형식의 폴더는 그대로는 안 읽힌다(13번의 `_xlfn._LONGTEXT` 가 「모르는 함수」로 걸리고 범위 지문이 없다). 옮기는 길: `책.json` 에 `"허용함수": ["_xlfn._LONGTEXT"]` 를 적고 → `python 범위지문.py 승인 <폴더> --위치범위` → `python 줄무늬.py --다시쓰기 <폴더>`. 수리 전 커밋의 `줄명세/` 로 해 보니 지금 정본과 시트 파일 13개가 같아졌다.
- `줄명세/` 는 새 형식으로 다시 뽑아 두었다. 키트 원본의 스캐폴드에서 뽑은 것과 파일 단위로 같다(13개 시트 파일 · 옛서식 · 책.json · 범위지문.json).

## 6. 사용자 판단 없이 정한 것과 까닭

| 정한 것 | 까닭 |
|---|---|
| 「위치로 읽는 범위」 = `INDEX` · `MATCH` · 짝 범위 **+ 바로 감싼 함수가 합계 함수(`SUM` · `MAX` · `MIN` · `COUNT` · `COUNTA` · `AVERAGE` · `PRODUCT` · `SUMSQ`)가 아닌 모든 여러 줄 범위** | 결정문이 「`COUNTBLANK` 등」이라 했다. 빈 칸·낯선 줄에 값이 달라지는 함수를 하나씩 꼽기보다 값이 안 달라지는 쪽을 꼽는 편이 안전하다(틈 점검과 같은 가름) |
| 합계 범위의 승인 표시 = 짓기의 `합계범위승인` 또는 승인 명령으로 고친 지문 | 「바뀐 목록을 내고 승인 표시가 있어야 짓는다」. 지문 파일의 diff 가 승인의 기록으로 남는다 |
| 묶음에서 열이 빠지면 **경고**(위험한 종류) — 위치로 읽는 묶음 범위여도 오류로 안 올림 | 검증의 권고가 「한 번 알린다」다. 묶음은 짝인 시트에서 함께 줄면 뜻이 유지되고, 짝이 어긋나면 짝 범위 점검이 오류로 잡는다. 오류로 올리면 `E11` 을 뺄 때 「고칠 곳의 목록」(뺀 열 참조 8건)이 묻힌다 |

| 오류 상수는 `#REF!` 만 막음 | 검증이 지적한 것이 `#REF!` 다. `#N/A` 는 `IFERROR(#N/A, …)` 처럼 뜻 있게 쓰인다(합성 통합문서에 있다) |
| 낯선 함수는 `책.json` 의 「허용함수」에 있을 때만 받음 | 스캐폴드에 `_xlfn._LONGTEXT` 가 있어, 함수 이름을 오류로 올리면 스캐폴드 자체가 안 지어진다. 옛 수식의 것만 받고 손으로 새로 적는 오타는 막는다 |
| 13번의 검증 구획을 시험 배치에서 뺌 | 엑셀의 수식 길이 한도. 수식을 바꾸는 것은 이 수리의 범위가 아니다(3단계) |

| `명세/`(칸 단위 기준선)를 지움 | 시험이 더는 갱신하지 않으므로 두면 낡는다. 첫 커밋에 남아 있다 |

## 2차-3. 남은 한계 · 못 고친 것

못 고친 것은 없다. 알아야 할 한계:

1. 1차의 한계 1 · 2 · 5 · 6 · 7 은 그대로다(13번 검증 구획의 수식 길이 · 옮긴 줄은 더한 묶음 열로 안 는다 · 글 속 좌표 · 넓어진 범위의 구조 대조 · 값 대조의 판별력).
2. **수식 꼴 점검이 못 보는 것**: 인자 수 표에 없는 함수의 인자 수 · 인자의 종류(참조가 와야 할 자리의 상수). 괄호 안의 합집합 쉼표(`SUM((A,B))`)는 엑셀 문법으로는 맞지만 받지 않는다(함수 밖 쉼표와 가릴 수 없어서 — 스캐폴드 · 하이닉스 · 예시에는 없다).
3. **덧붙인 이름은 이름이 같은 줄끼리의 틀린 ID 를 못 잡는다**(`· 비관` 이 80줄, 「시트 상태」가 11줄이다). 이름 장치의 본디 한계다. 범위는 범위 지문이 따로 잡는다.
4. 줄 이름표에는 옛 이름을 넷까지 남긴다(덧명세 없이 먼저 다시 쓴 뒤에도 가려지게). 그래서 「지금은 다른 줄의 이름인 옛 이름」으로 틀린 ID 를 적으면 줄 이름 고침으로 본다(드물다).
5. **범위 끝의 새 줄**: 끝 줄에 안 붙어 있고 그 범위를 읽는 줄도 여섯 줄 넘게 떨어져 있으면 못 알린다. 배치로 끼운 새 줄에는 걸지 않는다(배치 길은 「범위에넣기」·「범위허용」 표시로 한다 — 1차 그대로).
6. `예측.끝` · `예측.첫` 표기는 무늬 · 글 · 값의 열쇠에서만 다시쓰기가 지킨다. 「입력」·「병합」의 열 구간에 적으면 읽히지만 다시 쓸 때 열 ID 로 돌아간다.
7. 펼쳐지는 함수(`UNIQUE` · `SORT` · `FILTER` …)는 펼쳐지지 않는다(그 칸에 첫 값만). `SUM(…)` 따위로 감싼 값은 맞다(엑셀로 확인). 짓기가 경고로 알린다.
8. 함수 표는 이 컴퓨터의 엑셀(16.0 빌드 20430)에서 확인한 154개다. 더 새로운 함수는 「모르는 함수」로 막힌다 — 표에 더하고 `함수표확인.py` 로 견준다.
9. 검증을 모은 배치는 병합 경고 때문에 명령줄 종료 코드가 2 다(`--경고허용` 이면 0). 15번 시트의 열을 설계대로 잡을 때 병합할 열을 붙여 두면 경고가 없어진다.

## 2차-5. 다음 단계가 알아야 할 것 — 1차 5절에서 바뀐 곳

### 손 수식

- **이웃 열은 `@<-1>` · `@<+1>` 로 적는다.** `[행]@-1` 은 오류다. 설계 문서(`설계/6_산식_설계.md` 등)의 손 수식에 적힌 `@-1` 은 `@<-1>` 로 옮겨 적는다.
- 뒤에 나온 함수(`IFNA` · `IFS` · `XLOOKUP` · `TEXTJOIN` · `MAXIFS` …)는 **접두 없이** 적는다. 짓기가 `_xlfn.` 을 붙인다.
- 수식의 꼴이 틀리면 짓기 전에 멈춘다(파일 이름 · 줄 번호 · 무엇이 틀렸는지). `수식문법.md` 8 · 13절.

### 배치로 줄의 시트 이동(1차 5-1)

적는 법은 그대로다. 달라진 것 하나: 옮긴 줄의 병합이 풀리면 「병합」 경고가 한 건 난다(위험한 경고 — 명령줄 종료 코드 2). 뜻한 것이면 `--경고허용`.

### 범위 지문 승인 절차(1차 5-2 를 대신한다)

```
python 범위지문.py 보기 줄명세 --덧명세 새시트/S14.jsonl 새시트/S15.jsonl     # 지문과 다른 곳(갈래별로). 같으면 종료 코드 0
python 범위지문.py 승인 줄명세 --덧명세 …                                     # 합계 범위 · 범위 끝의 새 줄만 바뀌었을 때
python 범위지문.py 승인 줄명세 --덧명세 … --위치범위                           # 위치로 읽는 범위 · 가정묶음 · 짝 수 · 시트 머리 · 새 시트까지
```

| 명세에서 한 일 | 짓기의 답 | 푸는 길 |
|---|---|---|
| 합계 범위 안에 줄을 끼움 · 뺌 | 오류 「범위 지문 (합계 범위)」 | `승인`(또는 한 번만 `짓기 --합계범위승인`) |
| 범위의 끝 줄 곁에 새 줄(범위의 끝 ID 는 그대로) | 위험한 경고 「범위 끝의 새 줄」 — 새 줄이 범위에 안 든다 | 넣을 줄이면 범위의 끝 ID 를 고친다(그러면 합계 범위가 바뀐 것으로 다시 승인). 뜻한 것이면 `승인` |
| 위치로 읽는 범위(`INDEX` · `MATCH` · `COUNTIF` · `COUNTBLANK` · 짝 범위)의 줄을 끼움 · 뺌 · 옮김 · 가정묶음 · 짝 수 | 오류 「범위 지문 (위치로 읽는 범위)」 | `승인 --위치범위` |
| **시트 머리**를 고침 — 열을 더함 · 뺌 · 차례 · `종류` · `묶음` 표 · `축` · `쓰임` 의 별칭 | 오류 「범위 지문 (위치로 읽는 범위)」(「머리가 지문과 다르다」) | `승인 --위치범위`. 기간 열 개편이 이 길을 지난다 |
| 새 시트 파일(덧명세)을 더함 | 오류(그 시트의 지문이 없다) | `승인 --덧명세 <그 파일> --위치범위` — 지문은 그 파일의 폴더에 적힌다 |
| 범위가 뒤집힘 · 순환 · 가정 머리 줄의 세 줄이 깨짐 · 짝 크기 | 오류(구조) | 승인으로 못 푼다. 명세를 고친다 |

`범위지문.json` 은 손으로 고치지 않는다. diff 가 승인의 기록이다 — 명세와 함께 커밋한다.

### 명세를 고치는 순서(1차 5-3 을 대신한다)

1. `줄명세/S*.jsonl` 을 고친다. 까닭은 그 줄의 `"메모"` 에. 코드로 고칠 때는 `줄무늬.시트읽기` → 고침 → `줄무늬.시트쓰기`.
2. 줄 이름을 고쳤으면 `python 줄무늬.py --다시쓰기 줄명세 --덧명세 새시트/S14.jsonl 새시트/S15.jsonl`. 출력의 「덧붙인 이름을 고쳤다」 목록을 읽는다.
   멈추면(「줄 이름을 고친 것으로 볼 수 없는 덧붙인 이름이 있다」) 그 수식의 **행 ID 를 본다.** ID 가 맞고 이름만 틀리게 적은 것이면 덧붙인 이름을 손으로 고친다.
3. `python 범위지문.py 보기 …` → 바뀐 것을 확인하고 승인(위 표).
4. `python 짓기.py 줄명세 <배치> <낼 xlsx> <지도> --덧명세 …` — 종료 코드 0(2 면 위험한 경고를 읽는다).
5. 구조 대조 → 엑셀 재계산 → 값 대조. 커밋(`줄명세/` 의 시트 파일 · `범위지문.json` · `줄이름.json` 을 함께).

### 그 밖에

- 명세 폴더에 **`줄이름.json`** 이 생겼다(줄 이름표). 손으로 고치지 않는다 — 다시쓰기와 새로 뽑기가 적는다. 커밋한다.
- 12번 시트 머리에 `"가정묶음": true` 가 있다. 이 표시가 있는 시트에서만 좌표 지도의 가정묶음을 낸다.
- **옛 형식(줄무늬 2)의 사본**을 갖고 있으면: `python 줄무늬.py --옛꼴고치기 <폴더> [--덧명세 …]` → `python 범위지문.py 승인 <폴더> [--덧명세 …] --위치범위`.
- 열 구간 열쇠: 묶음의 끝 열 하나는 `예측.끝`, 첫 열 하나는 `예측.첫`. `E11` 로 적으면 그 열에 못 박힌다(스캐폴드에 3곳 — 2번 26 · 8번 12 · 12번 21번 줄. 줄마다 열 번호가 수식에 박혀 있어 3단계에서 수식부터 고쳐야 한다).
- 「글」에는 글, 「값」에는 숫자. 「덧」은 메모 · 링크만. 배치의 「칸」·「덧칸」에 수식을 주려면 `{"손수식": "=…"}`.
- 좌표 지도의 형식은 안 바뀌었다(가정묶음은 12번 것만 실린다 — 전에도 스캐폴드에는 12번에만 있었다).

## 2차-6. 사용자 판단 없이 정한 것과 까닭

| 가정묶음을 시트 머리의 표시로 가림(12번) | 재검증의 두 안 가운데 「명세에 표시」. 시트 ID 를 코드에 박지 않는다 |

| 새 시트(덧명세)도 지문이 있어야 짓는다 | 시트 머리의 지문이 모든 시트에 있어야 4-2 가 닫힌다. 새 시트를 더할 때 한 번 승인하면 된다 |
| 괄호 안의 합집합 쉼표를 받지 않음 | 함수 밖 쉼표(`=A,B` → `#VALUE!`)와 토큰으로 가릴 수 없다. 쓰는 곳이 없다 |

2. **기간 열 개편**: 시트 머리를 고치면 범위 지문 오류가 난다 — `승인 --위치범위` 로 적는다. 승인 전에 `보기` 가 내는 「묶음 … 의 열: 든 열 / 빠진 열」을 읽는다.
3. **키트 결합**: `좌표.py` 가 옮긴 줄의 지도를 읽는 것을 확인했다(03:41 판). 생성기 쪽에서 더 할 일은 없다. 좌표 지도의 형식은 이번에 안 바뀌었다.
4. **준비(W0d)**: `반영.py` 가 `행등록부.tsv` 를 놓으려는 자리 `구현/생성기/명세/` 는 1차 수리에서 없어졌다(시험이 `산출/명세_스캐폴드` 에 뽑는다). `--이름표만` 으로 돌리거나 자리를 고친다. 이름표를 반영해 줄 이름이 바뀌면 2차-5 의 순서(다시쓰기 → 승인)를 밟는다.
5. **배치 설계**: 15번 시트로 모을 구획 머리의 병합(11곳)이 풀린다. 15번의 열을 잡을 때 병합을 살릴지 정한다(살리려면 병합에 들던 열들이 15번에서 붙어 있어야 한다).
6. **총괄**: 결정문은 고치지 않았다. 「이웃 열 표기는 연산자와 겹치지 않게」는 이제 코드가 따른다.
