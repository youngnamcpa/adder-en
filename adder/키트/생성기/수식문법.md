# 손 수식 문법

줄 무늬 명세(`줄명세/S*.jsonl`)와 배치의 수식은 모두 이 문법으로 적는다. 엑셀 수식에서 **칸 주소만** 바꿔 적는 문법이다 — 함수·연산자·숫자·문자열은 엑셀 그대로다. 읽고 쓰는 코드는 `공통.py`의 `손수식틀`(글 → 틀)과 `손수식쓰기`(틀 → 글)다.

## 1. 한눈에

```
=[S04R054 매출액 합계]@. - [S05R017 매출원가 합계]@.        같은 열
=[S04R054]@. / [S04R054]@<-1> - 1                           직전 열(@<-1>) · 다음 열(@<+1>) — 꺾쇠로 싼다
=[S12R024 기간 길이]@$E1                                    고정 열(열 ID). $ 는 절대 표시
=[$S12R013 시나리오 번호]@$값                               행도 절대 표시 · 열은 그 줄 쓰임의 별칭
=SUM([S05R010]@.:[S05R016]@.)                               범위
=INDEX([$S04R054]@$예측,[$S12R028]@$H1)                     열 묶음(같은 줄의 「예측」 열 전부)
=COUNT([S12R031]@예측영구:[S12R033]@예측영구)               여러 줄 × 열 묶음
=[$S02R034]@$예측.끝                                        묶음의 끝 열(첫 열은 .첫)
="매출은 "&TEXT([S04R054]@.,"#,##0")&" 이다"                문자열 상수 안은 건드리지 않는다
```

## 2. 참조 하나의 모양

```
[ $? 행ID  덧붙인이름? ] @ !? $? 열
```

| 자리 | 뜻 |
|---|---|
| `행ID` | 줄의 ID. `S04R054` = 명세의 4번 시트 파일에 적힌 54번 줄(가정 번호). 배치를 바꿔도 안 바뀐다. 시트는 따로 적지 않는다 — **행 ID 는 이름일 뿐이고, 그 줄이 놓이는 시트는 배치가 정한다.** 수식의 시트 머리는 짓기가 「그 줄이 지금 놓인 시트」로 쓴다(11절) |
| `덧붙인이름` | 행 ID 뒤에 한 칸 띄고 적는 줄 이름. 읽는 사람을 위한 것이지만 **안전장치**이기도 하다. 짓기는 ID 만 쓰되, 덧붙인 이름이 지금 줄 이름과 다르면 **멈춘다**(3절) |
| `[$…]` | 행 절대 표시(`G$54`의 `$`) |
| `@$…` | 열 절대 표시(`$G54`의 `$`) |
| `@!…` | 같은 시트인데도 시트 이름을 붙여 쓴다(`'12. 가정_시나리오'!D5`). 옛 수식 글을 그대로 살릴 때만 쓴다 |
| `열` | 아래 4절 |

절대 표시는 **값에 영향이 없다**(생성기는 수식을 칸마다 따로 짓는다). 옛 수식 글과 글자 그대로 같게 하려고 싣는다. 새로 쓰는 수식에는 안 붙여도 된다.

## 3. 행 — ID 로 부르고 이름은 덧붙인다

- 열쇠는 ID 다. 줄 이름을 고쳐도 수식은 안 깨진다.
- 덧붙인 이름은 읽는 사람을 위한 것이다. 줄의 이름 전체나 **짧은 이름**(줄표·괄호·쌍점 앞까지, 24자까지, 대괄호는 소괄호로·큰따옴표는 작은따옴표로)과 같으면 통과다.
- 다르면 짓기가 「덧붙인 이름」 **오류**로 멈춘다(줄·이름 짝마다 한 번, 몇 곳인지 함께). 행 ID 를 한 줄 틀리게 적은 것을 이름이 잡아 준다.
- 다른 까닭은 둘 가운데 하나다. 짓기가 갈라서 알린다(`줄명세/줄이름.json` — 줄마다 마지막으로 맞춰 둔 이름 — 에 견줘서).
  - **줄 이름을 고쳤다**(덧붙인 이름이 그 줄의 옛 이름과 같다) → `python 줄무늬.py --다시쓰기 줄명세 [--덧명세 새시트/S14.jsonl …]` 로 맞춘다.
    다시쓰기는 고친 것을 낸다(행 ID · 옛 덧붙인 이름 → 새 이름 · 곳 수). 줄 이름표도 새 이름으로 고쳐 적는다.
  - **행 ID 를 틀리게 적었을 수 있다**(덧붙인 이름이 그 줄의 옛 이름과도 지금 이름과도 다르다) → 손으로 본다. 다시쓰기는 이것을 **덮지 않고 멈춘다**
    (아무것도 쓰지 않는다). 행 ID 가 맞고 이름만 틀리게 적은 것이면 덧붙인 이름을 손으로 고친다. 확인한 뒤 한꺼번에 덮으려면 `--이름덮기`(덮은 것을 낸다).
- 이름을 일부러 안 맞추고 지을 때만 `짓기(…, 이름불일치허용=True)` / 명령줄 `--이름경고허용`(경고로 남고 명령줄은 종료 코드 2).
- 생성기가 쓴 명세는 한 수식에서 같은 줄의 이름을 **처음 한 번만** 덧붙인다.
- 한 줄에 이름표가 둘인 줄(12번 4~13행: 이름·값 / 이름2·값2)은 가리키는 칸에 맞는 이름을 덧붙인다 — `[$S12R006 금액 단위 라벨]@$값2`.
- 배치의 `"별칭": {"매출합계": "S04R054"}` 표에 적은 이름도 행 ID 자리에 쓸 수 있다(띄어쓰기 없는 이름).
- **명세에 없는 행 ID 는 오류다**(`[S04R540]` — 자릿수가 뒤바뀐 것, 지운 줄을 가리키는 것). 옛 xlsx 에서 갓 뽑은 명세만 예외다: 옛 수식이 끝 줄 아래의 빈 줄을 읽고 있으면 `책.json` 에 `"등록부밖허용": true` 가 실리고, 그런 줄은 끝 줄에서 떨어진 만큼 밀어 준다(경고).

## 4. 열

| 표기 | 뜻 |
|---|---|
| `@.` | 같은 열 — 이 수식이 놓인 칸의 열 ID 와 **같은 ID** 의 열(다른 시트를 가리켜도 같은 ID) |
| `@<-1>` `@<+1>` `@<-k>` | 직전 열 · 다음 열 · k칸 앞 열. 꺾쇠로 싼다. 시간축 열에서는 시간축 열끼리 센다(아래 「차례」) |
| `@이름` `@근거1` `@기준일` | 고정 열 — 열 ID. **시간축 열은 열 ID 로 적지 않는다**(회차마다 열 ID 가 다르다 — 4-나절). 자리 이름으로 적는다 |
| `@판정` `@값2` `@기준` | 그 줄 쓰임의 별칭(5절) |
| `@예측` `@실적` `@시간` | 열 묶음 — 같은 줄의 그 묶음 열 전부(범위). 6절 |
| `@예측.끝` `@실적.첫` | 자리 이름 — 묶음의 끝 열 · 첫 열(칸 하나). 열 수가 바뀌어도 따라간다 |
| `@시간.2` `@예측.끝2` | 자리 이름 — 묶음의 앞에서 k번째 · 끝에서 k번째 열(`.1` = `.첫`, `.끝1` = `.끝`). 그 자리에 열이 없으면 오류 |
| `@예측<-1>` `@예측<-k>` | 묶음 안에서 k칸 앞 열 — 묶음을 벗어나면 그 참조는 숫자 0 이 된다(15절. W3a) |
| `@*` | 모든 열(행 전체 참조). 7절 |

**이웃 열은 꺾쇠로 싼다** — `[행]@<-1>-1` 은 「직전 열에서 1을 뺀다」, `[행]@.-1` 은 「같은 열에서 1을 뺀다」. 연산자와 겹치지 않는다.
옛 표기 `[행]@-1` 은 받지 않는다(오류 — `[행]@.-1` 에서 점을 빠뜨린 것과 가릴 수 없다). 옛 표기로 적힌 명세는
`python 줄무늬.py --옛꼴고치기 <명세 폴더>` 로 한꺼번에 고친다(14절).

**차례** — 직전·다음 열을 세는 순서:

- 이 칸이 시간축 열(종류가 실적·예측·영구)이면 **새 배치의 시간축 열끼리** 센다. 가운데에 다른 종류의 열이 끼어도 건너뛴다. 예측 열이 늘면 영구 열의 `@<-1>` 은 새 마지막 예측 열이다.
- 그 밖의 열이면 **명세의 열 순서**로 센다(배치가 더한 새 열은 건너뛴다 — 옛 수식의 뜻이 안 바뀐다).
- 배치가 더한 새 열(시간축 아님)의 칸에서는 새 배치의 열 순서로 센다.
- 셈한 열이 가리키는 시트에 없으면 오류다.

## 4-나. 시간축 열 — 기간에서 받는다 (W2)

시간축 열은 명세에 못 박혀 있지 않다. 회차의 가정 파일 `기간`(결산월 · 실적연도수 · 상세추정연수 · 수렴연수)과 평가기준일에서 키트의
`기간축.py` 가 축을 짓고, 생성기(`기간열.py`)가 그 축으로 열을 세운다. **열 ID = 기간 ID** 다(`FY2024A` · `1H26A` · `2H26E` · `FY2027E` · `TV`).

- **틀** — 명세의 시트 머리에는 시간축 「틀 열」 15개(H1 H2 H3 · E1~E11 · TV)가 `"갈래"`(· `"구간"`)와 함께 적혀 있다. 폭 · 접힘 따위를 갈래마다
  첫 틀 열에서 받는다. `책.json` 의 `"기본기간"` 이 이 틀의 꼴(실적 2 + 누계 · 잔여 + 상세 5 · 수렴 5 · 영구)을 낸다 — 꼴이 다르면 읽다가 멈춘다.
- **읽는 두 꼴** — `줄무늬.읽기(폴더, 기간=None)`: 기간을 안 주면 **틀 그대로**(열 ID H1 … — 명세를 고치는 도구 「다시쓰기 · 범위지문 · 이름입히기」가
  읽는 꼴), 기간(가정 사전 · 가정 파일 · 축)을 주면 **그 회차의 열**로 편다(워크북은 이 꼴로 짓는다 — `짓기.py --기간 <가정.json>` ·
  `배치_납품.py --기간` · `키트에넣기.py --기간`). 축으로 읽은 명세는 `쓰기`(다시쓰기)가 받지 않는다.
- **갈래** — 열마다 꼬리표가 있다: `FY실적` · `누계실적`(평가기준일이 결산일이 아닐 때 한 열) · `잔여예측`(같을 때 한 열) · `연간예측` · `영구`,
  예측 열에는 구간 `상세` · `수렴`. 개월 수가 정수가 아닌 열은 `달아님`. 묶음(6절)이 종류 대신 갈래를 모을 수 있다.
- **자리 이름** — 수식 · 열쇠에서 시간축의 한 열은 `묶음.첫` · `묶음.끝` · `묶음.k` · `묶음.끝k` 로 적는다(`@$실적.끝` = 마지막 실적 열 ·
  `@$예측.첫` = 첫 예측 열 · `@$수렴.첫`). 틀(안 모양)에도 풀지 않고 실려 짓기가 그 배치의 열로 푼다. 쓰임의 별칭도 자리로 정한다(5절).
- **빈 묶음** — 그 회차에 없는 갈래의 묶음(누계가 없는 회차의 `누계` · `잔여`, 수렴연수 0 의 `수렴`)을 **열쇠**로 적은 칸은 놓이지 않는다. 수식 안에서
  빈 묶음(· 그 자리)을 읽으면 오류다 — 그 갈래의 열쇠로 적은 무늬에서만 읽는다(`"수렴": "=…@$수렴.첫…"` — 수렴 열이 없으면 이 무늬도 놓이지 않는다).
- **`"축값"`** — 줄의 열쇠 `"축값": {"시간": "표기"}` 는 그 열의 기간 속성(표기 · 구분 · 종료일 · 시작일 · 개월 · 구간 · 회계연도 …)을 칸에
  상수로 적는다(12번의 시점 머리 줄). 같은 칸의 무늬보다 앞선다. 다른 시트의 시점 머리는 12번의 그 줄을 수식으로 읽는다.
- 좌표 지도에는 `기간열`(`[{id, 구분}]`) · `기간`(축) · 시트마다 `틀`(틀 열의 옛 열 글자 · 쓰임의 틀 자리)이 실린다. 축마다 지문이 다르다.

## 5. 열 ID · 종류 · 쓰임(별칭)

열 ID 는 시트마다 `열표.py`가 정한다(줄 무늬 명세의 첫 줄 「열」에 실린다). 시간축 열(아래 표의 H1 … TV)은 틀의 ID 다 — 지을 때 기간 ID 로 바뀐다(4-나절).

| 시트 | 열 ID (옛 열 글자 순서) |
|---|---|
| 2 · 5~10번 | 여백 · 이름 · 단위 · H1 H2 H3(실적) · E1~E11(예측) · TV(영구) |
| 4번 | 위와 같고 + 보조글 · 보조값 |
| 12번 | 위와 같고 + 근거1~근거4 · 방향 · 방향점검 · 역산 |
| 13번 | 여백 · 이름 · 단위 · H1 H2 H3 · 출처 · 기준일 · 확인상태 · 소비처 |
| 1번 | 여백 · 이름 · 단위 · 값1 값2 값3 · 풀이 |
| 3번 | 여백 · 이름 · 단위 · 예측값 · 영구값 · 출처 · 기준일 · 확인상태 · 비고 |
| 11번 | 여백 · 이름 · 단위 · 장부 · 조정 · 평가 · 세효과 · 순평가 · 비고 |

같은 열이 줄에 따라 달리 쓰인다. 줄마다 **쓰임** 하나를 달 수 있고(줄 무늬 명세의 `"쓰임"`), 그 줄의 칸과 그 줄을 가리키는 참조는 별칭으로 적는다.

| 쓰임 | 별칭 → 열 ID | 어느 줄 |
|---|---|---|
| 점검 | 판정 → 시간.1 · 사유 → 시간.2 (13번: 실적.1·실적.2 + 보조1 → 기준일, 1번: 값1·값2, 3번: 예측값·영구값 + 보조1·보조2, 11번: 장부·조정) | 검증 구획의 줄 |
| 설정 (12번) | 값 → 시간.1 · 이름2 → 시간.3 · 값2 → 시간.4 · 설명 → 시간.5 | 12번 4~13행(기준 정보·스위치) |
| 시점 (12번) | 비관 → 시간.1 · 기준 → 시간.2 · 낙관 → 시간.3 · 적용 → 시간.4 | 시나리오 서술(16~19행)·시점 가정(211~220행 등) |
| 단일 (2·4~10·12번) | 값 → 시간.1 · 값b → 시간.2 · 값c → 시간.3 | 시간축 시트에서 시간축을 안 쓰는 줄 — 값이 첫 값 열 한 칸에만 있다(가치 브리지 · 영구가치 · 스위치) |
| 시나리오 (1번) | 비관 → 값1 · 기준 → 값2 · 낙관 → 값3 | 1번 44~64행 |

별칭은 **그 줄의 쓰임에서만** 찾는다. 그 줄의 쓰임에 없는 별칭은 오류다 — 다른 쓰임에서 빌려 풀지 않는다(시점 줄의 `@값` 이 비관 칸이 되는 일이 없게). 쓰임이 없는 줄은 열 ID 로 부른다. 줄의 `"쓰임"` 값은 그 시트 머리의 쓰임 표에 있는 이름이어야 한다. 생성기가 쓴 명세는 줄에 쓰임이 있으면 별칭으로, 없으면 열 ID 로 적는다.

별칭으로 적은 칸은 **시간축이 아니다.** `[$S02R068 주당가치]@$값` 은 「그 줄의 값 칸」이지 「첫 실적 열」이 아니다. 별칭은 시간축의 **자리**(앞에서 k번째 열)로
정해져 있어 열 ID 가 회차마다 달라도 같은 칸을 가리킨다. 시간축의 열을 뜻으로 가리킬 때는 자리 이름으로 적는다 — `@$실적.끝`(마지막 실적 열 ·
옛 `@$H3`) · `@예측.첫`(옛 `@E1`) · `@$예측.끝`(옛 `INDEX(범위, 열 위치)`) · `@영구`(옛 `@TV`). 시간축 열 ID(틀의 `H3` · `E1` · `TV`, 축의 `FY2025A`)를
수식이나 열쇠에 그대로 적지 않는다 — 정본에는 0곳이다.

## 6. 범위와 열 묶음

```
[행1]@열1:[행2]@열2          범위(두 끝)
[행]@묶음                    같은 줄의 묶음 전부            [S04R054]@$예측  =  $G54:$Q54
[행1]@묶음:[행2]@묶음        여러 줄 × 묶음                 [S12R031]@예측영구:[S12R033]@예측영구  =  G31:R33
```

- 묶음은 열 **종류**(실적 · 예측 · 영구 …)나 **갈래**(4-나절)의 모음이다(줄 무늬 명세 첫 줄의 `"묶음"`). 시간축 시트: `실적` · `예측` · `영구` · `예측영구` ·
  `시간`(실적+예측+영구)과 갈래 묶음 `FY실적` · `누계` · `잔여` · `연간` · `상세` · `수렴` · `달아님`. 12번은 `근거`(근거1~4)가 더 있다.
- **묶음으로 적은 범위는 묶음이 늘면 따라 는다.** 배치가 종류 「예측」인 새 열을 더하면 `@예측` 은 그 열까지다. 열 ID 구간(`[행]@E2:[행]@E11`)은 안 는다.
- 묶음의 열은 새 배치에서 한데 붙어 있어야 한다(사이에 다른 열이 끼면 오류).
- 줄의 쓰임이 별칭을 준 열(시점 가정의 비관·기준·낙관 = H1·H2·H3)을 읽는 범위는 묶음으로 적지 않는다 — `[S12R212]@$비관:[S12R212]@$낙관`. 실적 열 수가 바뀌어도 늘면 안 되는 범위다.
- 범위의 두 끝은 같은 시트(명세의 같은 시트 파일)여야 한다. 배치가 줄을 다른 시트로 옮길 때도 범위의 줄은 통째로 함께 옮겨야 한다 — 두 끝이 다른 시트에 놓이면 오류다.
- 범위는 **위에서 아래로** 적는다(첫 끝이 명세에서 더 위). 뒤집히면 오류다. 수식이 놓인 칸이 제 범위 안에 들어도 오류다(순환).
- 범위의 구성 줄은 `범위지문.json` 에 적혀 있다. 명세에서 범위 안에 줄을 끼우거나 빼거나 옮기면 짓기가 알아챈다(12절).

## 7. 그 밖의 참조

```
[S12*]@$여백:[S12*]@$단위        열 전체 ($A:$C). 행 자리에 「시트ID*」
[$S12R003]@*:[$S12R007]@*        행 전체 ($3:$7). 열 자리에 *
세율                             정의된 이름 — 그대로 적는다
[S12*]!세율                      시트 안에서만 쓰는 정의된 이름
⟦'1. 자료:Plain'!E3⟧             틀로 못 바꾸는 참조(여러 시트 참조·다른 파일 참조) — 원문 그대로. 짓기가 경고한다
```

## 8. 안 되는 것

- **좌표를 그대로 쓰면 오류다**(`=G54*2`). 행 ID 와 열 ID 로 적는다.
- **수식의 꼴이 틀리면 오류다.** 엑셀은 이런 수식이 든 파일을 못 열거나 오류값을 내는데, 어느 수식인지는 알려 주지 않는다. 그래서 짓기 전에 멈춘다(13절).
  - 「=」로 시작하지 않는 무늬 · 괄호 짝이 안 맞음 · 연산자나 쉼표로 끝남 · `#REF!`
  - 연산자가 빠짐(`[A]@. [B]@.` · `(A)2` · `"a"1` — 두 값이 연산자 없이 이어진다) · 연산자가 둘 이어짐(`*/` · `>=<`) · 연산자로 시작(`=*A` · `==A`) · 빈 괄호 `()` · 함수 밖의 쉼표(`=A,B` · `(A,B)`)
  - 자주 쓰는 함수의 인자 수(`IF` 2~3 · `IFERROR` 2 · `INDEX` 2~4 · `MATCH` 2~3 · `ROUND` 2 … — `공통.인자수표`). 닫는 괄호를 한 칸 앞에 적은 겹친 `IF` 가 여기 걸린다
  - 엑셀 함수 목록에 없는 함수 이름(`SUMM`). 옛 xlsx 에 있던 낯선 함수(스캐폴드의 `_xlfn._LONGTEXT`)는 `책.json` 의 `"허용함수"` 에 실려 있는 동안만 받는다
  - `LET` · `LAMBDA` 와 LAMBDA 를 받는 함수(`MAP` · `BYROW` …)는 못 적는다(이름 인자에 `_xlpm.` 접두가 필요하다)
  - 엑셀이 받는 꼴은 둔다: 빈 인자(`IF(a,1,)`) · 퍼센트(`A%`) · 머리의 `−`(`A*-B`)
- **「=」로 시작하는 글을 「글」·「값」에 그대로 적으면 오류다**(문법을 거치지 않은 수식이 된다). 글이면 `{"v": "=…", "t": "s"}`, 수식이면 「무늬」에 손 수식으로 적는다.
- 문자열 상수 안의 `[…]@…` 는 글이다. 바뀌지 않는다. 글 속 좌표(「E28」「12번 30행」)도 안 옮겨진다 — 글에서 좌표를 빼고 번호 + 이름으로 부른다.
- `INDIRECT` · `OFFSET` · `ROW` · `COLUMN` · `ADDRESS` · `VLOOKUP`(열 번호) 는 틀로 못 바꾼다. 쓰이면 짓기가 경고한다.
- 덧붙인 이름에 대괄호 `[ ]` 와 큰따옴표 `"` 는 못 쓴다(소괄호·작은따옴표로 바꿔 적는다).

## 9. 줄 무늬 명세의 열 구간(무늬 · 글 · 값 · 입력 · 병합의 열쇠)

수식을 어느 열들에 놓는지는 열 구간으로 적는다. 구간 안의 칸마다 같은 손 수식을 그 칸의 열에서 읽는다(`@.` 과 `@<-1>` 이 칸마다 달라진다).

| 열쇠 | 뜻 |
|---|---|
| `이름` · `판정` | 열 하나(시간축이 아닌 열의 ID 또는 그 줄 쓰임의 별칭) |
| `근거1~근거4` | 열 ID 구간(시간축이 아닌 열) |
| `예측` · `시간` · `연간` | 묶음 전부(그 종류 · 갈래의 열이 늘면 따라 는다). 그 회차에 없는 갈래의 묶음은 빈 구간이다 — 칸을 놓지 않는다 |
| `예측.끝` · `예측.첫` · `시간.4` · `수렴.첫` | 자리 이름 — 묶음의 끝 열 · 첫 열 · k번째 열 하나. 열이 늘면 따라간다(「다시쓰기」가 이 표기를 지킨다) |
| `시간.4~시간.6` · `예측.2~예측` | 구간 — 두 끝에 자리 이름이나 묶음 이름(첫 자리의 묶음 = 그 첫 열, 끝 자리의 묶음 = 그 끝 열) |

같은 칸에 열쇠가 둘 걸리면 오류다(「값이 두 번 적혔다」) — 갈래 묶음으로 갈라 적는다(`실적` · `잔여` · `연간` · `TV`). `"축값"` 만 같은 칸의 무늬보다 앞선다.
시간축 열을 틀의 열 ID 로 적은 열쇠 · 낱말(`E1` · `@$H3`)은 틀로 읽을 때는 읽히지만 **회차의 워크북을 지을 때 오류다**(그 열이 없다) — 적지 않는다.
영구 열만은 틀과 축에서 ID 가 같아(`TV`) `"TV"` · `@TV` 로 적어도 된다. 다시쓰기는 적은 열쇠를 그대로 지킨다.

```json
{"id":"S05R017","이름":"매출원가 합계","단위":"=[$S12R006 금액 단위 라벨]@$값2","종류":"합계","서식":"금액",
 "무늬":{"실적":"=[S13R063 매출원가]@.","예측영구":"=SUM([S05R010 원가 항목 1]@.:[S05R016 신제품·증설 원가]@.)"}}
{"id":"S04R013","이름":"매출 구분 1 매출액","단위":"=[$S12R006 금액 단위]@$값2","종류":"계산","서식":"금액",
 "무늬":{"실적":"=[S13R086 매출 구분 1]@.",
        "잔여":"=IF(COUNT([$S13R086 매출 구분 1]@$실적.끝:[$S13R091 기타]@$실적.끝)>0,[S04R012 매출 구분 1 매출액]@.-[$S13R086]@$실적.끝,[S04R012]@.*[S04R195 잔여 기간 비율]@.)",
        "연간":"=[S04R012 매출 구분 1 매출액]@.*[$S12R432 기간]@.","TV":"=[S04R012 매출 구분 1 매출액]@.*[$S12R432 기간]@."}}
{"id":"S12R021","이름":"구분","종류":"머리","축값":{"시간":"표기"},"글":{"근거1":"근거 · 출처"}}
```

### 긴 수식·긴 글 — 조각으로 나눠 적기

무늬·글·이름·단위·메모의 값은 글 하나 대신 **조각의 목록**으로 적을 수 있다. 읽을 때 이어 붙인다(사이에 아무것도 안 넣는다).
행 하나가 여러 줄에 걸쳐도 된다(파일은 JSON 객체가 이어진 꼴이다). 「다시쓰기」는 400자를 넘는 행을 열쇠마다 한 줄로,
110자를 넘는 글을 쉼표·`&` 뒤에서 끊은 조각으로 적는다 — 한 조각만 고치면 diff 가 그 줄만 보인다.

```json
{"id": "S10R028", "이름": "실적 유효세율 범위", "종류": "점검", "쓰임": "점검",
 "무늬": {
  "판정": [
   "=IF(AND([S10R021 유효세율]@$H3>=0,",
   "[S10R021]@$H3<=0.5),\"OK\",\"확인 필요\")"]},
 "메모": "0~50% 밖이면 확인 필요 — 사유 칸을 채우면 신호로 내린다"}
```

- `메모` 는 사람이 적는 풀이다. 짓기는 안 읽고 「다시쓰기」가 지킨다(줄에도, 시트 머리에도, 열 등록부에도 적을 수 있다). `//` 주석 줄은 못 쓴다.
- `글` 에는 글만, `값` 에는 숫자·참거짓만 적는다(`"값": {"E1": "1000"}` 은 오류 — 글 칸이 된다). 날짜는 `{"v": "2026-06-30", "t": "d"}`.
- `덧` 은 `{열 ID: {"메모": …, "링크": …}}` 만 받는다. 값·수식의 틀(`f`)·모르는 열쇠는 오류다(수식은 `무늬` 에 손 수식으로).
- `병합` 의 구간이 한 줄 안에서 겹치면 오류다(엑셀이 파일을 못 연다).
- 열 등록부의 `종류` 는 열 종류 등록부(`줄무늬.열종류들` — 여백 · 이름 · 단위 · 번호 · 실적 · 예측 · 영구 · 값 · 풀이 · 근거 · 보조 · 비고 · 방향 · 방향점검 · 역산 · 소비처 · 점검칸 · 기타)나 그 시트의 묶음·축에 나오는 이름이어야 한다. 묶음·축에 적은 종류는 그 종류의 열이 있어야 한다.
- `높이` 는 줄 높이다. 새로 적는 줄은 이것으로 준다(옛 서식 파일의 높이보다 앞선다).
- 열쇠의 차례는 정해져 있다(id · 이름 · 단위 · 종류 · 서식 · 쓰임 · 선 · 들여 · 굵게 · 높이 · 입력 · 무늬 · 글 · 값 · 병합 · 덧 · 메모). 손으로는 아무 차례로 적어도 되고 「다시쓰기」가 맞춘다.
- 모르는 열쇠 · 같은 열쇠 두 번 · `종류`/`서식`/`쓰임` 값의 오타 · 파일의 시트와 다른 시트 머리의 행 ID 는 오류다. 오류에는 파일 이름과 줄 번호가 붙는다.
- 명세를 코드로 고칠 때는 `줄무늬.시트읽기(경로)` → `(머리, 줄들)` 을 고쳐 `줄무늬.시트쓰기(경로, 머리, 줄들)` 로 적는다(표준 꼴로 적힌다).

## 10. 틀(안에서 쓰는 모양)

손 수식은 읽으면 **틀**이 된다 — 글 조각과 참조 dict 의 목록. 짓기는 틀에서 새 좌표의 수식 글을 낸다.

```
"=SUM(" , {"k":"r","x":0,"r":"S05R010","c":"E1","a":"..","r2":"S05R016","c2":"E1","a2":"..","fn":…} , ")"
```

`k` 종류(c 칸 · r 범위 · C 열 전체 · R 행 전체 · n 정의된 이름 · x 못 바꿈) · `x` 시트 이름이 붙었나 · `a` 절대 표시(열, 행) · `g` 묶음 이름(묶음으로 적은 범위) · `fn`/`arg` 감싼 함수와 인자 번호(위치로 읽는 범위인지 가리는 데 쓴다) · `w`/`w2` 열을 적은 법(`.` 같은 열 · `n` 이웃 열(`@<-1>`) · `i` 열 ID 를 못 박음 · `a` 별칭 · `e` 묶음의 첫·끝 — 짓기가 「못 박은 열」을 셀 때 쓴다. 틀을 견줄 때는 안 본다).

왕복은 **틀 → 손 수식 글 → 틀** 이 같다는 뜻이다(시험 4). 손으로 쓴 글을 읽어 다시 쓰면 표준 꼴(별칭·묶음·`@.`)로 바뀔 수 있다.

## 11. 줄이 놓이는 시트 — 배치가 정한다

행 ID 의 `S04` 는 「명세의 4번 시트 파일에 적힌 줄」이라는 이름일 뿐이다. 배치는 그 줄을 어느 시트의 `행` 목록에든 실을 수 있다.

```json
{"id": "S15", "이름": "15. 검증",
 "열": ["번호", "이름", "단위", "판정글", "미결", "표시", {"새열": "판정", "종류": "점검칸"}, {"새열": "사유", "종류": "점검칸"}],
 "행": ["S15R001", "…", {"빈줄": 1}, "S04R058", "S04R059", "…", "S04R064"],
 "열맞춤": {"S04": {"H1": "판정", "H2": "사유"}}}
```

- 옮길 줄은 놓을 시트의 `행` 에 적고 본 시트의 `행` 에서는 뺀다(`뺄줄` 에는 안 적는다 — 빼는 것이 아니다).
- **수식은 안 고친다.** 수식은 행 ID 로 적혀 있어 어느 시트에 놓여도 같은 줄을 가리킨다. 짓기가 시트 머리만 다시 쓴다:
  - 옮긴 줄을 읽던 다른 시트의 수식 → 놓인 시트의 이름으로(`='15. 검증'!G43`)
  - 옮긴 줄이 「같은 시트의 다른 줄」을 읽던 수식 → 다른 시트 참조가 된다(`COUNTIF('5. COGS_working'!G22:R22,"<0")`)
  - 함께 옮겨 온 줄끼리, 또는 옮겨 가서 같은 시트에 모인 줄끼리 → 시트 머리 없이
- 옮긴 줄의 칸은 `열맞춤`(본 시트의 열 ID → 놓인 시트의 열 ID)을 거쳐 놓인다. 안 적은 열은 같은 ID 의 열에 놓인다. 값이 있는 칸의 열이 놓인 시트에 없으면 오류다.
- 그 줄의 수식이 쓰는 열 표기(`@판정` · `@.` · `@E1`)는 **본 시트의 것 그대로** 둔다. 그 줄을 가리키는 참조도 본 시트의 열 ID·별칭으로 부른다(`[S04R064]@판정`) — 짓기가 `열맞춤` 으로 놓인 열을 찾는다.
- 범위는 양 끝이 같은 시트에 놓였을 때만 선다. 범위의 줄을 일부만 옮기면 오류다(통째로 옮긴다).
- 참조마다 시트 머리가 붙으므로 수식이 길어진다. 8,192자를 넘으면 오류다(스캐폴드의 13번 111·113번 줄은 15번으로 옮기면 9,798자가 된다 — 수식을 보조 칸으로 나눈 뒤에 옮긴다).
- 좌표 지도의 `행시트`(옮긴 줄 → 놓인 시트)와 `열맞춤` 이 자리를 싣는다. `지.새주소` · `지.주소` 는 놓인 시트의 이름을 돌려준다.
- 옮긴 줄 안의 병합은 병합에 들던 열들이 놓인 시트에서도 붙어 있을 때만 남는다. 풀리면 짓기가 「병합」 경고로 **한 번** 알린다(위험한 경고 — 명령줄 종료 코드 2).

## 12. 범위 지문 — 명세를 손으로 고친 뒤

`줄명세/범위지문.json` 에는 시트마다 **시트 머리**(열 차례 · 축을 이루는 열 · 묶음마다 열 ID 목록 · 쓰임의 별칭), 여러 줄 범위마다 구성 줄 ID 목록,
가정묶음(머리 줄 + 세 시나리오 줄), 서로 짝인 범위의 수, 줄 ID 목록이 적혀 있다. 짓기는 지금 명세와 견준다.

| 바뀐 것 | 짓기의 답 |
|---|---|
| 위치·빈 칸으로 읽는 범위(`INDEX` · `MATCH` · 짝 범위 · `COUNTBLANK` · `COUNTIF` …)의 구성·순서 | **오류** |
| 합계 범위(`SUM` · `MAX` · `MIN` · `COUNT` · `AVERAGE` …)의 구성 | 바뀐 목록을 내고 멈춘다. 승인 표시(`--합계범위승인`)가 있으면 경고로 낮춰 짓는다 |
| 가정묶음이 기준에서 빠지거나 바뀜 · 짝 범위의 수가 줄어듦 | **오류** |
| 시트 머리가 바뀜 — 열의 `종류` · `묶음` 표 · `축` · 열 차례 · `쓰임` 의 별칭(묶음으로 적은 범위·무늬가 말없이 줄거나 는다) | **오류**(`--위치범위` 로만 승인한다) |
| 범위의 끝 줄 곁에 지문에 없던 줄이 생김 — 끝 줄에 바로 붙은 새 줄, 또는 끝 줄과 그 범위를 읽는 줄 사이(옛 줄 다섯 줄 안)의 새 줄. 범위의 열에 값·수식·입력 칸이 있는 줄만 | **위험한 경고** 한 번(「범위 끝의 새 줄」 — 새 줄이 합계·점검 수에 들지 않는다). 범위의 끝 ID 를 고치거나, 뜻한 것이면 승인한다 |
| 범위의 두 끝이 뒤집힘 · 수식이 제 범위 안(순환) · 지문에 가정묶음으로 적힌 머리 줄의 `INDEX` 가 바로 아래 세 줄이 아님 · 짝 범위의 크기가 다름 | **오류**(승인으로 못 푼다 — 명세를 고친다) |

가정묶음(좌표 지도가 붓기에 주는 「머리 줄 + 비관·기준·낙관 세 줄」)은 시트 머리에 `"가정묶음": true` 가 있는 시트(12번)에서만 찾는다.
다른 시트에서 `INDEX` 줄 바로 아래에 둔 선택 표는 몇 줄이든 그냥 표다 — 새 범위로 승인(`--위치범위`)하면 지어지고, 가정묶음에 실리지 않는다.

```
python 범위지문.py 보기 줄명세 --덧명세 새시트/S14.jsonl 새시트/S15.jsonl      # 지문과 다른 곳을 본다
python 범위지문.py 승인 줄명세 --덧명세 …                                      # 합계 범위만 바뀌었을 때 — 지문을 고쳐 적는다
python 범위지문.py 승인 줄명세 --덧명세 … --위치범위                            # 위치로 읽는 범위·가정묶음·짝 수가 바뀐 것까지 승인
```

범위 지문은 손으로 고치지 않는다. 「다시쓰기」도 건드리지 않는다. 바뀐 목록을 눈으로 확인하고 승인 명령으로만 고친다(지문 파일의 diff 가 승인의 기록이다).
새 시트 파일(덧명세)을 처음 더할 때도 그 시트의 지문이 없으므로 승인(`--위치범위`)이 있어야 지어진다.

## 13. 함수 — 엑셀 그대로 적는다. 새 함수의 접두는 짓기가 붙인다

- 함수 이름은 엑셀 그대로 적는다. 쓸 수 있는 이름 = 2007년 파일 형식 표준의 함수(openpyxl 의 목록 355개) + 그 뒤에 나온 함수(`공통.새함수` 154개).
- **뒤에 나온 함수**(`IFNA` · `IFS` · `SWITCH` · `XLOOKUP` · `TEXTJOIN` · `CONCAT` · `MAXIFS` · `STDEV.S` · `RANK.EQ` · `NORM.S.DIST` · `RRI` · `AGGREGATE` …)는
  xlsx 에 `_xlfn.` 접두와 함께 적혀야 엑셀이 안다. 접두 없이 적히면 엑셀이 `_xludf.` 를 붙이고 `#NAME?` 이 된다.
  **손 수식에는 접두 없이 적는다**(`=IFNA(…)`). 짓기가 수식 글을 낼 때 붙인다(`SORT` · `FILTER` 는 `_xlfn._xlws.`). 이미 붙여 적은 것은 그대로 둔다.
- 표는 엑셀에 수식을 적어 저장한 파일에서 확인한 것이다. `python 함수표확인.py` 가 다시 견준다(시험 6 이 함께 돌린다).
- 값을 여러 칸에 펼쳐 내는 함수(`UNIQUE` · `SORT` · `FILTER` · `SEQUENCE` · `VSTACK` …)는 **펼쳐지지 않는다** — 생성기는 수식을 칸마다 적는다.
  그 칸에는 첫 값만 나온다. `SUM(…)` · `INDEX(…, n)` 으로 감싸 값 하나를 받는 것은 맞다. 쓰이면 짓기가 「펼쳐지는 함수」 경고로 알린다.
- `LET` · `LAMBDA` · `MAP` · `REDUCE` · `SCAN` · `BYROW` · `BYCOL` · `MAKEARRAY` · `ISOMITTED` 는 못 적는다(오류).

## 14. 옛 형식의 명세를 옮기기

`책.json` 의 `"형식"` 이 `줄무늬 1` · `줄무늬 2` 인 폴더는 이웃 열을 `@-1` 로 적는다. 그대로는 읽지 않는다(오류가 옮기는 길을 알린다).

```
python 줄무늬.py --옛꼴고치기 <명세 폴더> [--덧명세 새시트/S14.jsonl …]     # @-1 → @<-1> · 「가정묶음」 표시 · 줄 이름표 · 형식
python 범위지문.py 승인 <명세 폴더> [--덧명세 …] --위치범위                    # 범위 지문을 새 형식(시트 머리 · 줄 목록)으로
```

정본(`줄명세/`)은 이 길로 옮겨 두었다. 옮긴 것은 스캐폴드에서 새로 뽑은 것과 파일 단위로 같다.

## 15. 구조에 따라 펴는 줄 — 되풀이 · 갈래 · 시나리오 세 줄 · 표 구획 (W3a)

`기간` 이 열을 정하듯 가정 파일의 `구조` 가 줄을 정한다(설계/6_산식_설계.md 6-1 · 6-5). 줄 명세의 줄 하나는 **틀**일 수 있다 — 읽을 때
(`줄무늬.읽기(폴더, 기간=가정, 구조=가정)` · `짓기.py --기간 가정.json` · `키트에넣기.py --납품 --기간 가정.json`) `구조펴기.py` 가 구조 선언대로 편다.
편 줄은 보통 줄과 같아서 납품 배치 · 범위 지문 · 좌표 지도는 편 줄만 본다. 구조가 없는 읽기(틀 읽기 — 다시쓰기 · 범위 지문 · 이름입히기)는
책.json 의 `"기본구조"`(없으면 빈 구조)로 편다. 돌려 볼 수 있는 보기: `보기_구조얹기.py`(정본의 사본에 얹어 납품 배치로 짓는다 — 시험 12 의 9부).

**책.json 에 적는 것**

```json
"되풀이": {"s": "매출구분", "j": "매출구분[].라인", "p": "투자.프로젝트", "n": "@예측", "y": {"부터": 0, "까지": "@가정:시점가정.857"}},
"구조기본": {"환율": {"경로": "없음"}, "매출구분[]": {"경로": "증가율", "라인[]": {}}, "투자": {"프로젝트[]": {"리드타임": 0}}},
"시나리오칸": "[$S12R013 시나리오 번호]@$값"
```

- `되풀이` — 변수 → 구조의 목록 경로. 목록의 항목은 셈에서는 그 `번호`(없으면 차례)이고 점으로 키를 읽는다(`s.경로` · `p.리드타임`).
  `"매출구분[].라인"` 은 겹친 목록이다 — 부모 변수(s)가 묶여 있으면 그 구분의 라인만, 아니면 모든 구분의 라인을 차례로(이때 s 도 함께 묶인다).
  `"@예측"` 은 예측 열(1 … 예측 열 수. `n.열` = 기간 ID). `{부터, 까지}` 는 정수 구간 — 끝값은 정수 · 식 · `"@가정:경로"`(가정 파일의 값. 구조 지문의 재료가 된다).
- `구조기본` — 구조의 기본값. 사전은 키마다, 목록 항목의 기본은 `"이름[]"`. **식이 구조에 없는 키를 읽으면 오류**이므로 식이 읽는 키는 여기에 기본을 둔다.
- 변수 이름은 구조의 맨 위 키와 겹치면 안 된다.

**줄에 적는 열쇠**

| 열쇠 | 뜻 |
|---|---|
| `"되풀이": "s"` · `["s", "j"]` | 그 변수의 값마다 줄을 짓는다. **이어진 줄들이 같은 변수로 시작하면 한 묶음**으로 되풀이한다(s = 1 의 줄들, s = 2 의 줄들 …). 묶음 안에서 `["s", "j"]` 인 줄은 그 구분의 라인마다 |
| `"묶음끝": true` | 이 줄에서 묶음을 끊는다 — 다음 줄이 같은 변수여도 따로 되풀이한다(줄마다 되풀이) |
| `"조건": "식"` | 참일 때만 짓는다. 거짓이면 좌표 지도 `구조.안지은줄` 에 까닭과 함께 남는다(붓기가 그 번호에 쓰려 하면 자리가 없다) |
| `"갈래": [ … ]` | `{"조건": "식", 덮을 열쇠…}` — 참인 것마다 차례로 덮는다 / `{"고름": "식", "값1": {…}, "값2": {…}, "그밖": {…}}` — 식의 값과 같은 이름의 것 하나(없고 「그밖」도 없으면 오류). 무늬 · 글 · 값 · 칸서식은 열쇠 단위로 덮고(`null` 이면 그 열쇠를 뺀다) 그 밖(이름 · 단위 · 종류 · 서식 · 입력 …)은 통째로. `"짓지않음": true` 를 덮으면 그 줄을 짓지 않는다 |
| `"시나리오": "예"` + `"적용열": "예측"` | 머리 줄에 적용값 수식 `=INDEX(세 줄, 시나리오 번호)` 가 서고 바로 아래에 비관 · 기준 · 낙관 세 줄(입력 · 들여 2 · 머리 줄의 서식)이 선다. **세 줄의 번호** — 가정 번호 500 미만은 머리 + 1 · 2 · 3, 500 이상은 머리 × 10 + 1 · 2 · 3 (`S12R610` → `S12R6101~6103`). 좌표 지도의 `가정묶음` 에 실린다. 그 줄 안에서 `{머리}` · `{비관}` · `{기준}` · `{낙관}` 자리를 쓸 수 있다 |
| `"시나리오": "예"` + 쓰임이 시점 꼴 | 세 줄을 짓지 않고 `적용` 칸의 수식만 짓는다(비관 · 기준 · 낙관 · 적용 네 칸) |
| `"시나리오": "공통"` | 한 줄(그 줄이 곧 입력 칸). 짓는 것은 없고 좌표 지도의 `줄속성` 에 실린다 |
| `"빈칸허용": true` | 적용값 수식을 `=IF(INDEX(…)="","",INDEX(…))` 로 짓는다 — 빈칸이 0 이 되지 않는다. 읽는 쪽은 `ISNUMBER(칸 하나)` 로 가른다(시험 12 의 8부: 엑셀 = formulas) |
| `"표": "T1"` · `"표머리": "T1"` | 표 구획의 줄 · 그 표의 열 머리 줄(칸 이름이 글로 선다. 「머리글」이 덮는다) |
| `"칸서식": {열 구간: 서식}` | 그 칸만 다른 숫자 서식 |
| `"대조": false` | 엔진 = 워크북 대조에서 그 줄을 뺀다(W3c). 종류가 계산 · 소계 · 합계 · 비율인 지은 줄은 **전부** 좌표 지도의 `대조줄` 에 실리고 키트의 대조가 그 표로 견준다 — 엔진이 그 번호를 안 내면 「엔진 미계산」이다. 글 · 날짜를 내는 줄, 점검 보조 줄, 도구 기입 칸처럼 견줄 수가 없는 줄에만 단다(`false` 만 적는다. 까닭은 `메모` 에 — 지도의 `견주지않는줄` 에 실려 화면에 나온다) |
| `"대조열": "예측영구"` | 대조할 열을 그 묶음(`전부` · `예측영구` · `예측` · `영구` · `실적`)에서 수식이 선 열로 좁힌다. 안 적으면 축의 전 열을 견준다(엔진이 값을 내지 않는 칸은 워크북이 빈칸 · 0 이어야 한다) |

**자리 채우기** — 틀인 줄(위 열쇠나 `{ }` 가 있는 줄)의 모든 글에서(id · 이름 · 무늬의 열쇠와 수식 · 입력 …).

```
S04R1{s}5                       정수 · 글의 값            S04R{68+3*(s-1):03d}        숫자 서식(:03d)
[S12R{668+2*j}]@.               셈(+ - * // %)            {p.이름} CAPEX              목록 항목의 키
={모두 p 「+」: [S12R86{p}]@예측<-{p.리드타임}>}          그 변수의 값마다 항을 지어 「+」로 잇는다. 하나도 없으면 0
={모두 s 만 s.경로 == '수준' 「+」: [S04R1{s}2]@.}        식이 참인 것만
=[S13R063]@.{모두 c 만 c != k 「」: -[S05R01{c}]@.}        잇는 글이 비고 항이 제 연산자(+ · -)로 시작하면 하나도 없을 때 빈 글
```

`{ }` 자리만 있는 줄(틀의 열쇠가 없는 줄)은 책.json 에 `되풀이` · `구조기본` · `기본구조` 가운데 하나라도 적은 명세에서만 틀로 본다 —
옛 스캐폴드에서 뽑은 명세의 배열 상수(`{1,2,3}`)를 건드리지 않으려는 것이다. 정본이 처음 틀을 올릴 때 책.json 에 그 열쇠를 적는다(절차 1).

식은 파이썬의 식 꼴이다 — 정수 · `'글'`(작은따옴표) · `+ - * // %` · 견줌(`== != < <= > >= in`) · `and or not` · `a if c else b` ·
`any all len max min sum int str abs` · `(x.키 for x in 목록 if …)`. 이름은 되풀이 변수 · 구조의 맨 위 키 · `기간`(`예측열수` · `실적열수` ·
`상세열수` · `수렴열수` · `누계` · `잔여`). 그 밖의 꼴(함수 부르기 · 밑줄 이름 · 나눗셈 `/`)은 오류다. 글에 중괄호 글자 자체는 못 쓴다.

**표 구획** (4-4) — 시트 머리에 `"표": {"T1": {"칸": ["기준기간", "매출액", …], "머리글": {"매출액": "매출액 (연환산)"}, "서식": {"시점": "연수"}}}`.
칸은 그 시트의 첫 값 열(시간축 열 · 값 열)부터 오른쪽으로 놓이고, 칸이 값 열보다 많으면 마지막 값 열 바로 뒤에 덧 열(`표덧1` … — 종류 「값」)이
선다(자료 열 6에 9칸 표면 3개. 근거 열은 그 뒤로 밀린다). 칸은 별칭이다 — `"입력": ["매출액~인원가중"]` · `"글": {"기준기간": "{s.기준기간}"}` ·
`[$S12R6{s}7]@$판매단가`. 칸에 `{"되풀이": "y", "칸": "Y{y}"}` 를 적으면 그 변수의 값마다 한 칸(Y0 … Yn). 줄이 하나도 서지 않은 표는 별칭도 덧 열도 없다.
좌표 지도의 `표구획`(`{시트: {표: {칸, 열, 줄}}}`)이 가정 파일의 `표.<번호>.<칸>` 이 들어갈 자리를 싣는다. 묶음 이름 `표칸` 은 생성기가 쓴다.

**`@묶음<-k>`** — 묶음 안에서 k칸 앞 열(설계의 「@예측-k」. 이웃 열 표기와 같이 꺾쇠로 싼다). 이 칸의 열에서 시간축으로 k칸 앞의 열이 그 묶음에 들면
그 열을 읽고, **묶음을 벗어나면 그 참조 자리에 숫자 0 을 적는다**(`[S12R862]@예측<-1>` 은 첫 예측 열에서 `0`). `<-0>` 은 같은 열이다.
범위의 끝으로는 못 쓴다. 이 표기를 쓴 무늬는 다시쓰기가 적힌 그대로 둔다. `@$예측.k` 는 k번째 예측 열(4절의 자리 이름 — 되풀이 `"@예측"` 과 함께 쓴다).

**지키는 것**

- 틀인 줄은 「다시쓰기」가 **적힌 그대로** 되돌려 적는다(열쇠 차례만 맞춘다). 덧붙인 이름을 맞춰 주지 않으므로 줄 이름을 고치면 손으로 맞춘다 — 자리를 채운 뒤의 이름과 견준다.
- 새 줄 · 표를 더하면 범위 지문을 승인한다(12절 — 시트 머리의 쓰임 · 묶음이 바뀌므로 `--위치범위`). 지문은 틀 읽기(기본구조)의 것이다.
- 짓기는 파일을 내기 전에 **칸 단위 고리 검사**를 한다(`고리검사.py` — 범위는 칸마다 편다). 고리가 있으면 「고리」 오류로 멈추고 파일을 내지 않는다.
- 좌표 지도에 싣는 것: `명세지문`(축 · 구조와 무관 — 명세 파일의 내용에서. 메모 · 줄 나눔 · 조각 가름은 무관) · `구조지문`(기간 다섯 값 + 가정의 `구조` + 명세지문 [+ `구조지문재료` 의 값] — `좌표지도.구조지문`. 12번 시트의 숨은 이름 `_구조지문` 에도 남는다) · `구조`(안지은줄 · 틀) · `줄속성` · `표구획` · `줄이름지문` · `이름칸` · `단위종류`.
- **조각 파일** — 책.json 의 `"조각": {"S12": ["S12_매출.jsonl", …]}`. 조각 파일의 첫 객체는 `{"조각": "S12"}`, 둘째부터 행이다. 시트 파일의 줄 뒤에 적힌 차례로 이어 읽는다(한 조각의 줄은 한데 붙는다). `시트읽기` · `시트쓰기` · 다시쓰기는 줄마다 온 파일로 되돌려 적는다.
