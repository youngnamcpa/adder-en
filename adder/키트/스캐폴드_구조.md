## 검증행 문법 (재계산 도구 호환 — 실측 근거)
- `SUMPRODUCT(--(…))` **금지** — formulas 패키지가 0으로 잘못 푼다. 부호 검사는 `COUNTIF(범위,"<0")`, 조건 검사는 `SUMPRODUCT((조건)*(조건))` 곱형. **범위끼리 비교(`(G31:Q31<G32:Q32)`)와 불리언 합(`(a)+(b)`)도 곱형 안에서 정상 작동(v6 실측)**.
- 여러 범위 SUMPRODUCT는 콤마형 대신 곱형.
- 사용 열만 세는 마스크: `SUMPRODUCT(('12. 가정_시나리오'!$G$22:$Q$22<>"")*(대상))`.
- 롤업은 「확인 필요*」 와일드카드로 센다. 「신호 …」·「해당 없음 …」·「OK (확인 불가 N건)」은 통과하되 눈에 남는다.
- **시트 상태 공통 패턴 (v6 → L5)**: `확인 필요* > 0 → 확인 필요` / `확인 불가* 또는 신호* > 0 → OK (확인 불가 N건 · 신호 M건)` / 그 외 OK — v12 판의 13개 시트 전부(v13 은 16시트 — 시트 상태 줄은 좌표 지도로 찾는다). **L5 에서 신호 수를 더했다** — 막지는 않되 1번 D75:D86 에서 보이게. 1!D123 은 「신호 있는 시트 N개」를 함께 적는다.
- **사유 강등 패턴(v6)**: 걸리는 행 옆 E열 사유 셀이 차면(`LEN(TRIM(E&""))>0`) 판정이 「신호 — … (사유 있음: E행)」로 바뀌어 롤업을 통과하되 눈에 남는다. 대상(실물 — 수식이 읽는 칸): 2!E74·2!E77·**3!E39(L5)**·5!E35·5!E36·**5!E38(L5)**·6!E29·**6!E31(L5)**·9!E30·**9!E31(L5)**·10!E28·10!E29·11!E46·12!E231·12!E232·12!E233. `가정_템플릿.json` 의 `사유` 가 이 목록과 같다. *(5!E34 는 판정이 상수(D34)라 사유 칸이 아니다 — L5 에서 템플릿에서 뺐다. 옛 라벨의 E207·E209 는 두 번 밀린 좌표였고 L5 에서 E231·E233 으로 고쳤다.)*
- **사유 글의 내용은 어떤 검증행도 검사하지 않는다** — 글자가 있으면 강등이다. 그래서 신호를 시트 상태에 드러내고, 11!D46 은 사유 글 앞부분을 판정에 병기한다.
- 「구조상 자동 성립 — 검사 대상 아님」 = 항진명제였던 행의 라벨 — 롤업에서 자동 제외. v6에서 여덟 곳 추가 정리(1!D124·3!D37·4!D40·5!D33·6!D27·8!D41(v10 **D47**)·10!D25·11!D45)와 중복 검사 세 곳 일원화(WACC>g → 2!D72, 주당>0 → 2!D78).
